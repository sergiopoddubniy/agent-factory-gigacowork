# Что здесь и чего здесь нет — база знаний пространства

Агент: Ассистент 1С-разработки (`demo-1c-dev-assistant`).

**Происхождение:** обезличено / реальное — по каждому файлу ниже; данных других клиентов нет.
**Режим:** фикстура — файлы загружаются в пространство и читаются агентом; живых вызовов нет.

## Что грузится

- `шаблон_ТЗ.md` — шаблон технического задания компании (7 разделов + реестр вопросов); источник для пилота — руководитель направления 1С
- `проверка/` — приёмочные кейсы с машинными признаками и файлы прогонов (П12, П13); агент их не читает как знание — это проверка

## Чего здесь нет и почему

- запрос бизнеса на доработку (письмо, тикет, протокол встречи) — свободный текст — не грузится: это вход, который пользователь приносит с каждым запросом, а не знание пространства.
- выгрузка описания конфигурации: список объектов метаданных с реквизитами и описаниями (txt/xlsx), сделанная штатными средствами — не грузится: это вход, который пользователь приносит с каждым запросом, а не знание пространства.
- шаблон технического задания компании (docx/markdown) — не грузится: это вход, который пользователь приносит с каждым запросом, а не знание пространства.
- для документации — описание сделанной доработки от разработчика (текст) и снимки форм — не грузится: это вход, который пользователь приносит с каждым запросом, а не знание пространства.
- Заполненные образцы результата — не грузятся: агент получил бы готовый ответ, и показ перестал бы что-либо показывать (заполненный лежит в запасном результате показа).
