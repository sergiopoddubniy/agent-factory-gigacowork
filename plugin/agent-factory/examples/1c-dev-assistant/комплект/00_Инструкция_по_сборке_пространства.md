# Инструкция по сборке пространства — Ассистент 1С-разработки

Единый чек-лист для администратора: порядок подтверждён практикой (`workspace_assembly.md`, «Мастер-инструкция сборки»). Каждый артефакт, который человек ставит руками, назван здесь отдельным шагом и лежит в поставке в одном экземпляре.

Поколение платформы: **2**. Конструктор принимает агента архивом; упаковка — шаг 6.

## Шаги

1. **Создать пространство**, видимость — личное на время сборки, командное к моменту показа (демонстрация).
2. **Загрузить базу знаний** целиком: папка `01_База_знаний_workspace/1_demo-1c-dev-assistant/` одним проходом, по карте состава `00_ЧТО_ЗДЕСЬ_И_ЧЕГО_ЗДЕСЬ_НЕТ.md` — что грузится и что намеренно нет.
3. **Создать навык агента** «Каталог навыков → Создать навык»: поля «Имя навыка», «Когда применять», «Категория» — из фронтматтера `04_Пакеты_агентов/1_demo-1c-dev-assistant_V5_24.09.26/00_Навык_demo-1c-dev-assistant.md`, тело файла — в поле «Инструкции». В поле «Имя навыка» вводится дословно `Ассистент 1С-разработки`: активация работает по совпадению имени.
4. **Создать агента**: поля карточки — из `04_Пакеты_агентов/1_demo-1c-dev-assistant_V5_24.09.26/01_Карточка_агента_demo-1c-dev-assistant.md` (название, описание, «Инструкция» с блоком активации первыми строками, перечень навыков).
5. **Создать команды** из `04_Пакеты_агентов/1_demo-1c-dev-assistant_V5_24.09.26/02_Команды_demo-1c-dev-assistant.md` — 5 команд, каждая со своим именем (с префиксом 1.), описанием и телом; первой — `1.0 Как со мной работать`.
6. **Упаковать архив для загрузки** (шаг человека перед самой загрузкой): структура `demo-1c-dev-assistant/skills/00-agent-skill/SKILL.md` (содержимое `00_Навык_demo-1c-dev-assistant.md`) + `demo-1c-dev-assistant/commands/run-agent.md` (тело команды `1.1`); готовый архив с SHA-256 лежит вне поставки, в `../demo-1c-dev-assistant_загрузка/` — сверить хеш из `СБОРКА.md`.
7. **Проверить задеплоенное состояние от лица не-администраторского аккаунта**: открыть агента, выполнить `1.0 Как со мной работать` и один эталонный запрос из приёмочных случаев навыка (§15); сверить результат по объёму и структуре. Скудный результат — не «модель так работает», а неподцепившийся навык.
8. **Приёмочный прогон**: случаи из `01_База_знаний_workspace/1_demo-1c-dev-assistant/проверка/evals_demo-1c-dev-assistant.md`, ответы агента целиком — в файл `прогон_<ГГГГ-ММ-ДД>.md` там же; вердикт — `python3 scripts/check_run.py --кейсы … --прогон …` (по форме), приёмщик — по существу.

## Три разные строки в handoff

- `delivery composition check` — комплект собран целиком (скрипт, `СБОРКА.md`);
- `structural audit` — структура пакета (скрипт, `СБОРКА.md`);
- `platform runtime validation` / `deployed state check` — агент работает и виден обычному участнику (человек в интерфейсе, шаг выше). Первые две не означают третью.
