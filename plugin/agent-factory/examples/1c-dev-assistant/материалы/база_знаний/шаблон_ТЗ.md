## 1. Цель и обоснование
Зачем нужна доработка, какую проблему бизнеса решает, кто заказчик.

## 2. Объекты конфигурации
Перечень затрагиваемых объектов метаданных (документы, справочники, регистры, обработки), что в них меняется. По каждому объекту — новые/изменяемые реквизиты с типом и обязательностью.

## 3. Функциональные требования
Пронумерованный список требований. По каждому: описание, условие срабатывания, ожидаемое поведение, источник требования (ссылка на запрос заказчика).

## 4. Печатные формы
Какие печатные формы затрагиваются и как. Если не затрагиваются — указать «не применяется» и причину.

## 5. Права доступа
Какие роли получают доступ к новым объектам/реквизитам, ограничения.

## 6. Миграция данных
Нужно ли заполнять новые реквизиты для существующих документов, как.

## 7. Критерии приёмки
Проверяемые условия, по которым заказчик принимает доработку (формат «шаг → ожидаемый результат»).

## Реестр открытых вопросов к заказчику
Вопросы, без ответа на которые разделы ТЗ не могут быть заполнены. Если вопросов нет — «пуст».
