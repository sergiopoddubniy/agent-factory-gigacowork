# outcome_hypothesis.md — гипотеза результата и её проверка

Агент делается не ради функции, а ради измеримого изменения в работе.
Блок 3 спецификации — обязательный, и он единственный, который
проверяется не при сборке, а после запуска. Работа фабрики не закрыта,
пока гипотеза не измерена либо явно не помечена «не подтверждена».

## Шесть полей

| Поле | Что писать | Провал |
|---|---|---|
| Метрика | что измеряется и в каких единицах: часы на задачу, дни от запроса до результата, доля принятого без правок, число обращений | «улучшить», «повысить эффективность» |
| Бейзлайн | текущее значение **и как измерено**: хронометраж N задач за период, журнал системы, выгрузка | «по словам руководителя», «примерно» — допустимо только как `Допущение:` для demo |
| Цель | целевое значение и защитная метрика, ниже которой результат не засчитывается (качество, переделки) | цель без защитной метрики: скорость за счёт качества |
| Опережающий индикатор | что сдвинется раньше основной метрики: доля черновиков без структурных правок, число обращений за помощью | «количество запусков агента» — не связано с результатом |
| Период подтверждения | 7 / 14 / 28 / 90 дней и на скольких задачах | период короче, чем природа метрики |
| Условие пересмотра | при каком значении к какому дню гипотеза не подтверждена и что делаем: ретро правил, новая гипотеза, откат | нет условия — гипотеза не фальсифицируема |

## Бейзлайн — лучшая ближайшая альтернатива

Сравнивать надо не с нулём и не с «как есть навсегда», а с тем, что было
бы сделано без этого агента: текущий способ работы, готовый инструмент,
уже работающий у клиента агент. Если у клиента есть похожее решение на
своём стеке — бейзлайн это оно, и агент фабрики доказывает разницу с ним
(часы сборки, доступность для бизнес-пользователя, срок до результата), а
не с пустотой.

## Что не считается

- Опросы участников «стало ли быстрее». Самооценка расходится с фактом на
  десятки процентных пунктов; в расчёт идут хронометраж, журналы, приёмка.
- Время, «сэкономленное» на задачах, которые никто не делал.
- Один и тот же эффект, посчитанный дважды: в часах и в сроке, у агента и у
  процесса.

## Формула для эффекта времени (когда метрика — часы)

Эффект = N × Δt/60 × C × q × k × охват, где N — число задач за период,
Δt — экономия минут на задачу (бейзлайн − факт), C — стоимость часа роли,
q — доля принятого без правок, k — коэффициент материализации (что из
сэкономленного времени действительно уходит в другую работу), охват — доля
задач, проходящих через агента. Из этих множителей агент влияет на Δt и q;
остальные — параметры организации, их не завышать.

## Проверка после запуска

1. Тот же способ измерения, что у бейзлайна: хронометраж — так
   хронометраж, журнал — так журнал.
2. Период подтверждения из блока 3, не раньше.
3. Результат вносится в файл приёмочного прогона: `Статус: подтверждена`
   или `Статус: не подтверждена`, `Измерено: …`.
4. Не подтверждена — выполняется условие пересмотра: правится
   спецификация (новая версия), пересобирается пакет, новый период.
5. `scripts/evidence_bundle.py --threshold pilot` — READY только со
   статусом, отличным от «не проверена».

## Связь с финансовой оценкой

Гипотеза результата — вход для расчёта финансового эффекта по стандарту
Альянса в сфере ИИ (АФИИНА): метрика и бейзлайн становятся карточкой
эффекта, период подтверждения — протоколом приёмки эффекта. Фабрика не
считает деньги; она даёт измеренные коэффициенты, по которым их считает
финансовая валидация.
