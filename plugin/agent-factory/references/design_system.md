# design_system.md — визуальный стиль сценария агента (.docx)

Проверенная на нескольких клиентах комбинация — не меняй без причины, она
уже читается как «фирменный» формат GigaCowork сценариев.

## Цвета

| Назначение | HEX | Где используется |
|---|---|---|
| Основной тёмно-синий (NAVY) | `1F3864` | Заголовки h1–h3, шапки таблиц (заливка), крупный титул |
| Акцентный золотой (GOLD) | `B8860B` | «СБЕР · GIGACOWORK» вверху титула, подзаголовки уровня h4 (например, «ПРИОРИТЕТ ИСТОЧНИКОВ:», названия few-shot примеров) |
| Серый (GREY) | `666666` | Подзаголовок «Сценарий AI-агента», курсивные пояснения |
| Светло-серый (LIGHT) | `F2F2F2` | Заливка левой колонки метатаблиц, заливка чётных строк в таблицах данных (zebra striping) |
| Белый | `FFFFFF` | Текст в шапке таблиц (на тёмно-синем фоне) |

## Шрифт

Calibri везде. Размеры (в half-points, как принимает docx-js):
- Крупный титул: 36
- h1 (номерные разделы «N. …»): 30
- h2 (подзаголовки типа «Описание», «Пространство»): 25
- h3 (emoji-заголовки типа «📚 ИСТОЧНИКИ ДАННЫХ»): 23
- h4 (золотой, «ШАГ N: …», названия few-shot): 21
- Обычный текст / ячейки таблиц: 21 (текст), 19–20 (ячейки таблиц, чтобы влезало)

## Таблицы

- Шапка таблицы: заливка NAVY, текст белый жирный.
- Тело: чередование белого и LIGHT (zebra) для таблиц данных; метатаблицы
  (Параметр/Значение) — левая колонка всегда LIGHT + bold, без чередования
  по строкам.
- Ширины колонок — задавать явно в DXA и на таблице, и на каждой ячейке
  (см. `docx` skill: PERCENTAGE ломается в Google Docs).
- Списки/файлы с длинными именами в узкой колонке иногда переносятся некрасиво
  (например, `имя_файла.d` / `осх`) — это некритично, но если колонка узкая и
  в ней в основном имена файлов, лучше сделать её на 10–15% шире.

## Структура страниц

- Разрыв страницы (`PageBreak` внутри `Paragraph`) после титула и после
  каждого из разделов 1, 2 (после few-shot), 3, 4, 5 — итоговый документ на
  10–14 страниц, что совпадает с ожидаемым объёмом для встречи на 30–40 минут.
- Поля страницы: 1000 DXA сверху/снизу, 1100 слева/справа, A4
  (`{ width: 11906, height: 16838 }`).

## Списки

Не вставляй `•` литералом — заводи `numbering` конфиг с `bullets` и
`numbered` референсами (см. `scripts/docx_helpers.js`), иначе список не
распознаётся Word'ом как настоящий список.

## Обязательная проверка перед сдачей

1. `soffice.py --headless --convert-to pdf <файл>.docx`
2. `pdftoppm -jpeg -r 100 <файл>.pdf page`
3. Посмотри как минимум: титул, таблицу формата вывода (эмодзи рендерятся
   как цветные кружки — это ок, это не баг), первую few-shot страницу,
   RAG-таблицу раздела 3, таблицу синтетики раздела 5, чеклист раздела 6.
4. Проверь орфографию в русском тексте внутри таблиц отдельно — таблицы реже
   попадают в общий read-through, а опечатки в них (например, в названиях
   типов возражений/категорий) потом расходятся по few-shot и RAG-файлам.
