# База шаблонов агентов — состав

**Происхождение:** синтетика либо обезличено. **Режим:** фикстура.

Оба вида допустимы и объявляются по набору: `синтетика` — придуманные данные,
`обезличено` — настоящие, из которых убрана принадлежность (так сделана
отчётность Клиент-Н). `реальное` в базе запрещено.

Здесь копятся готовые к копированию агенты. Правила, порог массы и порядок
попадания — `references/agent_templates.md`; здесь их пересказа нет.

Поиск — `python3 scripts/templates.py --похожие "<джоба>"`, индекс —
`--индекс` (`ИНДЕКС.md`). Шаблонов больше пяти, поэтому база читается
поиском, а не глазами: у каждого шаблона заполнены роль, джоба и «когда
применять».

## Что лежит

Восемнадцать шаблонов по пяти функциям; полный список с ролями и джобами —
`ИНДЕКС.md`.

- `Разработка 1С/demo-1c-dev-assistant/` — пример фабрики, синтетика: шаблоном
  служит сама спецификация `AGENT_SPEC.md`, навык, карточка и команды порождены
  из неё.
- `Логистика/` — восемь навыков демо-пакета для логистической платформы
  (ставка, рынок направления, проверка контрагента, публикация груза,
  переговоры, дебиторка, электронные перевозочные документы, перевозка в
  чужой сделке): навык и команда запуска.
- `Сбыт и маркетинг/` — пять агентов службы маркетинга промышленного
  производителя (разведка, сигналы спроса, отраслевые кампании, квалификация
  заявок, SEO): навык, карточка, команды, инструкция по сборке.
- `Закупки и тендеры/` — анализ тендерной документации, соответствие ТЗ и
  технического предложения, расчёт НМЦД.
- `Финансы/group-consolidation/` — консолидация отчётности группы с
  расчётным ядром: навык, команда запуска, описание движка и его инвариантов
  (`harness/README.md`), синтетическая база знаний. Код движка не входит —
  он собран под формы исходной группы и собирается заново по
  `references/computational_core.md`.

Все шаблоны, кроме примера 1С, — обезличенные наработки живых пилотов и
воркшопов: клиент, люди, контрагенты и домены заменены условными
(`Клиент-А`, `Клиент-П`, `Компания А`, `ДатаРеестр`, `example-*.ru`),
контакты — ролями, абсолютные суммы клиента убраны. Каждый несёт
`КАРТА_ПЕРЕНОСА.md` в три графы — заменить обязательно, проверить, не
трогать — с перечнем найденных в тексте условных имён, инструментов
коннекторов, файлов базы знаний и порогов.

В фабрике единица шаблона — спецификация: при переносе навыка из базы
пишется новая `AGENT_SPEC.md`, в неё берутся модули и правила шаблона, и
комплект порождается из неё заново. Навык рядом — чтобы шаблон читался и
находился поиском.

В витринную сборку для платформы база не входит (`scripts/build_hub.py`
оставляет только этот файл и индекс): агент на платформе собирается с нуля
по спецификации, а шаблоны нужны консультанту и прогонам.

**Пустая база — не «нормально», а долг** (`БЭКЛОГ.md`, С-69): пока её нет,
каждый следующий агент пишется с нуля рядом с уже собранным. Честный ответ
поиска на пустой базе — «кандидатов не было», и он записывается в комплект
(Я21), а не заменяется молчанием.

## Чего здесь нет и не будет

Признаков принадлежности: названий юрлиц, ИНН и ОГРН, адресов, фамилий,
номеров договоров. Числа — можно: на обезличенных наборах они и есть то, ради
чего набор берут. Нельзя, чтобы по набору узнавался клиент — включая случаи,
когда его выдаёт не имя, а сумма, редкая номенклатура или пара «дата плюс
регион».

Порогов и правил клиента, перенесённых без замены. Шаблон едет с
`КАРТА_ПЕРЕНОСА.md`, где сказано, что заменить обязательно; шаблон без карты
считается дефектом базы, а не удобным исключением.
