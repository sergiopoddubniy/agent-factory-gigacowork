# Инструкция по сборке — Агент № 5, Соответствие ТЗ и технического предложения

Пошагово, что куда вставить и в каком порядке — вручную, в реальном UI GigaCowork. Комплект пилотный: набор команд пересобран из воркшопного (6 вместо 8 — демонстрационные команды на синтетике убраны, см. `02_Команды_tz-tp-compliance.md`).

## Состав этого комплекта

- `SKILL.md` — источник истины: полная логика агента (модули, источники, критерии, HITL, ограничения). Из него сжаты поля карточки ниже. Дублируется в базу знаний пространства пилота — поле «Инструкция» ссылается на него по имени.
- `01_Агент_tz-tp-compliance.md` — готовые значения для формы «Создание агента»: Название, Описание, Инструкция, рекомендованные Навыки и Коннекторы.
- `02_Команды_tz-tp-compliance.md` — 6 слэш-команд для формы «Создать команду»: Имя, Описание, Инструкции.

## Порядок сборки

1. **Загрузить `SKILL.md` в базу знаний пространства**, в подпапку `5_tz-tp-compliance/` (вместе с остальными справочными файлами агента — они грузятся все сразу для всего пространства, см. `01_Регламент_сопровождения_и_каденция.md`).
2. **Создать агента.** Открыть `01_Агент_tz-tp-compliance.md` и построчно перенести: Название → поле «Название», Описание → поле «Описание», Инструкция (текст целиком, включая обязательный блок активации навыка первыми двумя предложениями — не сокращать и не переставлять) → поле «Инструкция».
3. **Прикрепить навыки и коннекторы** из списка в конце `01_Агент_tz-tp-compliance.md`: Не требуются — документный сценарий без внешних систем.
4. **Создать 6 команд.** Слэш-команды в GigaCowork — общий пул на пространство, поэтому имя каждой начинается с номера агента (`5.1`, `5.2` …). Для каждого блока `02_Команды_tz-tp-compliance.md` перенести Имя команды, Описание и Инструкции в форму «Создать команду».
5. **Проверить деплой не из администраторского аккаунта** — по правилу `platform_architecture.md`/`agent_package.md`: попросить одного из пилотных пользователей (не того, кто собирал агента) открыть его и выполнить стартовую команду `5.1`. Если навык не подхватился или команда не видна — пересобрать шаг 1–4, не откладывать проверку до общей демонстрации пилотной группе.

## Статус на старте пилота — что ещё не готово к production

Три эталонные пары ТЗ/ТП загружены в базу знаний полностью, но эталонный разбор конструктора (оракул для сверки точности) клиент пока не заполнил. Полный чек-лист — раздел 16 `SKILL.md`, сводный статус доступов по всем 7 агентам — `../../06_Карта_доступа_L1-L2-L3.md`.

## Проверка комплекта

Консистентность полей (числа, названия, ссылки команд на файлы базы знаний) проверена скриптом `build_agent_card.py --kb <база знаний агента>` — результат — см. `run_log.md`, раздел «Прогон гипотез / consistency_check».
