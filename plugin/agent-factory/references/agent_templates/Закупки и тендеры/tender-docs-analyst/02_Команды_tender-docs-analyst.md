# Слэш-команды — Агент № 2, Анализ тендерной документации (пилот)

5 команд для формы «Создать команду». Пересобрано под пилот из воркшопного набора (7 команд): убраны демонстрационные команды на синтетике (конфликт в требованиях, защита от prompt injection — правила остаются в `SKILL.md`, §§9–13), рабочая команда 2.1 переписана на приём реального комплекта от пользователя. Приёмочная команда на реальном комплекте Заказчик-Э перенесена без изменений — она уже работает на реальных данных.

---

## 2.1 Разбор тендерного комплекта

**Имя команды:** 2.1 Разбор тендерного комплекта
**Описание:** Основной рабочий режим. Стартовая команда.
**Инструкции:**
Пользователь прикладывает тендерный комплект (один или несколько файлов — извещение, ТЗ/ТТ, проект договора, формы заявки; форматы pdf/docx/xlsx/архив). Разбери его: построй опись по содержимому документов (не по именам файлов), извлеки требования в матрицу, собери чек-лист «проходим/не проходим/требует решения» с цитатами и топ-3 риска.

---

## 2.2 Как работает разведка по заказчику

**Имя команды:** 2.2 Как работает разведка по заказчику
**Описание:** Консультация без запуска реального прогона.
**Инструкции:**
Объясни, как ты проведёшь разведку по заданному заказчику: какие инструменты ДатаРеестр используешь, что покажешь в результате (победители за 2 года, повторяемость поставщиков) и как будешь действовать, если коннектор ДатаРеестр недоступен.

---

## 2.3 Разведка по заказчику — живой запуск

**Имя команды:** 2.3 Разведка по заказчику — живой запуск
**Описание:** Рабочий режим на реальном заказчике.
**Инструкции:**
Пользователь называет заказчика (название/ИНН). Проведи разведку: кто выигрывал его закупки за последние 2 года, с какой ценой, кто закрепился надолго. Коннектор ДатаРеестр в пилоте пока не развёрнут (см. §16 SKILL.md) — работай в режиме имитации, явно предупреди об этом первой строкой ответа и укажи, к кому обратиться (руководитель ИТ-инфраструктуры — инфраструктура, менеджер провайдера данных — доступ ДатаРеестр, <телефон менеджера провайдера>).

---

## 2.4 Массовая выгрузка закупок — лимиты

**Имя команды:** 2.4 Массовая выгрузка закупок — лимиты
**Описание:** Проверка HITL-паузы при большом объёме тарифицируемых запросов.
**Инструкции:**
Пользователь называет заказчика и период. Прежде чем выгружать все его закупки за период через ДатаРеестр, покажи остаток дневного лимита (`tenders_balance`) и, если расход превысит 10% дневного лимита, запроси подтверждение — не выполняй выгрузку без явного «да».

---

## 2.5 Приёмка: реальный тендер Заказчик-Э

**Имя команды:** 2.5 Приёмка: реальный тендер Заказчик-Э
**Описание:** Проверка на настоящем (не синтетическом) комплекте — приёмочный протокол. Без изменений унаследовано из воркшопа (была 2.7).
**Инструкции:**
Найди в базе знаний папку `калибровка/` — это реальный завершённый тендерный комплект АО «Заказчик-Э» (реконструкция технологического оборудования на площадке заказчика): `Тендер.docx`, `Документация о закупке.docx`, комплект `ТТ/` (техзадание, спецификация, требования к ЦО, режимные требования площадки), `Приложение №2 - ПРОЕКТ ДОГОВОРА.docx`, `Приложение №9 - ОБОСНОВАНИЕ НМЦ.docx` и формы заявки. Полная рабочая документация (`ТТ/РД/`, 17 файлов) в это пространство не загружена из-за объёма (см. `README_калибровка.md`) — построй опись и чек-лист по тому, что физически доступно, и явно отметь в выводе, что раздел РД не проверялся. Построй по остальному комплекту опись (по содержимому документов, а не по именам файлов), чек-лист «проходим / не проходим / требует решения» с цитатами и топ-3 риска. В конце явно укажи: это приёмочный прогон, результат нужно сверить построчно с независимым ручным разбором тендерного направления — протокол сверки описан в `README_калибровка.md` в этой же папке. Эталонный разбор для сверки клиент пока не заполнил (см. `09_Контур_улучшения/`) — до его получения это структурная проверка, не проверка точности.
