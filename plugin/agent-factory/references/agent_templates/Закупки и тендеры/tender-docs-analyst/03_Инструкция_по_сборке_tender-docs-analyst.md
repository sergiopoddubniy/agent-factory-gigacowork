# Инструкция по сборке — Агент № 2, Анализ тендерной документации

Пошагово, что куда вставить и в каком порядке — вручную, в реальном UI GigaCowork. Комплект пилотный: набор команд пересобран из воркшопного (5 вместо 7 — демонстрационные команды на синтетике убраны, см. `02_Команды_tender-docs-analyst.md`).

## Состав этого комплекта

- `SKILL.md` — источник истины: полная логика агента (модули, источники, критерии, HITL, ограничения). Из него сжаты поля карточки ниже. Дублируется в базу знаний пространства пилота — поле «Инструкция» ссылается на него по имени.
- `01_Агент_tender-docs-analyst.md` — готовые значения для формы «Создание агента»: Название, Описание, Инструкция, рекомендованные Навыки и Коннекторы.
- `02_Команды_tender-docs-analyst.md` — 5 слэш-команд для формы «Создать команду»: Имя, Описание, Инструкции.

## Порядок сборки

1. **Загрузить `SKILL.md` в базу знаний пространства**, в подпапку `2_tender-docs-analyst/` (вместе с остальными справочными файлами агента — они грузятся все сразу для всего пространства, см. `01_Регламент_сопровождения_и_каденция.md`).
2. **Создать агента.** Открыть `01_Агент_tender-docs-analyst.md` и построчно перенести: Название → поле «Название», Описание → поле «Описание», Инструкция (текст целиком, включая обязательный блок активации навыка первыми двумя предложениями — не сокращать и не переставлять) → поле «Инструкция».
3. **Прикрепить навыки и коннекторы** из списка в конце `01_Агент_tender-docs-analyst.md`: ДатаРеестр (MCP) — обязательно, для выгрузки комплектов и разведки по заказчику (tenders_*, registry_company_contracts).
4. **Создать 5 команд.** Слэш-команды в GigaCowork — общий пул на пространство, поэтому имя каждой начинается с номера агента (`2.1`, `2.2` …). Для каждого блока `02_Команды_tender-docs-analyst.md` перенести Имя команды, Описание и Инструкции в форму «Создать команду».
5. **Проверить деплой не из администраторского аккаунта** — по правилу `platform_architecture.md`/`agent_package.md`: попросить одного из пилотных пользователей (не того, кто собирал агента) открыть его и выполнить стартовую команду `2.1`. Если навык не подхватился или команда не видна — пересобрать шаг 1–4, не откладывать проверку до общей демонстрации пилотной группе.

## Статус на старте пилота — что ещё не готово к production

Коннектор ДатаРеестр не развёрнут — «разведка по заказчику» в имитации. Приёмка на реальном комплекте АО «Заказчик-Э» готова к прогону (команда 2.5), эталонный разбор клиента для сверки точности ещё не получен. Полный чек-лист — раздел 16 `SKILL.md`, сводный статус доступов по всем 7 агентам — `../../06_Карта_доступа_L1-L2-L3.md`.

## Проверка комплекта

Консистентность полей (числа, названия, ссылки команд на файлы базы знаний) проверена скриптом `build_agent_card.py --kb <база знаний агента>` — результат — см. `run_log.md`, раздел «Прогон гипотез / consistency_check».
