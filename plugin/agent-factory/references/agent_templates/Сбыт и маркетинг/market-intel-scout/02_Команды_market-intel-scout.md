# Слэш-команды — Агент № 1, Рыночная и конкурентная разведка (пилот)

4 команды для формы «Создать команду». Пересобрано под пилот из воркшопного набора (6 команд): демонстрационные команды на синтетике убраны (искусственный конфликт источников, проверка защиты от prompt injection — правила по ним остаются в `SKILL.md`, §§9–13, и продолжают действовать без отдельной команды), рабочие команды переписаны с фиксированных demo-файлов на приём реального параметра от пользователя в момент запуска. Файлы `demo/` в пространстве пилота отсутствуют — не ссылаться.

Реальных калибровочных данных для агента №1 на момент сборки пилота нет — калибровка на 3–5 реальных справках, упомянутая в SKILL.md §2, ещё предстоит на неделях 1–2 пилота (статус зависимостей — карта решения прогона, вне базы знаний агента).

---

## 1.1 Справка по компании

**Имя команды:** 1.1 Справка по компании
**Описание:** Основной рабочий режим. Стартовая команда — с неё имеет смысл начинать знакомство с агентом.
**Инструкции:**
Пользователь прикладывает название компании, ИНН или ОГРН (текстом в запросе или файлом — например, скрин карточки контрагента). Подготовь по этому запросу карточку компании: реквизиты, финансовая динамика, риски, что реально делала (подтверждённые контракты) vs что заявляет (номенклатура по сайту), признаки загрузки, вывод не более 3 рекомендаций. Каждый факт — с источником. Используй коннектор ДатаРеестр; коннектор в пилоте пока не развёрнут (см. §16 SKILL.md) — работай в режиме имитации и явно предупреждай об этом первой строкой ответа, пока коннектор не подключат.

## 1.2 Как отличаешь «делал» от «заявляет»

**Имя команды:** 1.2 Как отличаешь «делал» от «заявляет»
**Описание:** Консультация без входного файла — объяснение логики агента.
**Инструкции:**
Объясни без обращения к файлам, по каким признакам ты отличаешь «конкурент реально делал» (подтверждённые контракты и объекты) от «конкурент заявляет» (номенклатура на сайте без подтверждённых поставок), и как ты поступаешь, если признаки противоречат друг другу.

---

## 1.3 Анализ выгрузки — топ-10

**Имя команды:** 1.3 Анализ выгрузки — топ-10
**Описание:** Агрегация: ранжирование реального списка компаний.
**Инструкции:**
Пользователь прикладывает файл — реальную выгрузку из ДатаРеестр или иного реестра компаний (xlsx/csv). Проанализируй эту выгрузку и дай топ-10 приоритетных компаний с обоснованием ранжирования по каждой.

---

## 1.4 Массовая проверка — лимиты ДатаРеестр

**Имя команды:** 1.4 Массовая проверка — лимиты ДатаРеестр
**Описание:** Проверка HITL-паузы при расходе тарифицируемых лимитов на реальном списке.
**Инструкции:**
Пользователь прикладывает реальный список компаний для проверки (более 20 позиций). Прежде чем выполнять массовый прогон, покажи остаток по balance-проверке лимитов и запроси у пользователя подтверждение на продолжение — не запускай прогон без явного «да».
