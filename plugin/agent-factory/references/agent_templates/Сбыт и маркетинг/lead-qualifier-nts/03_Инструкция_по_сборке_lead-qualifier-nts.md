# Инструкция по сборке — Агент № 3, Квалификация заявок (цифровой НТС)

Пошагово, что куда вставить и в каком порядке — вручную, в реальном UI GigaCowork. Комплект пилотный: набор команд пересобран из воркшопного (4 вместо 6 — демонстрационные команды на синтетике убраны, см. `02_Команды_lead-qualifier-nts.md`).

## Состав этого комплекта

- `SKILL.md` — источник истины: полная логика агента (модули, источники, критерии, HITL, ограничения). Из него сжаты поля карточки ниже. Дублируется в базу знаний пространства пилота — поле «Инструкция» ссылается на него по имени.
- `01_Агент_lead-qualifier-nts.md` — готовые значения для формы «Создание агента»: Название, Описание, Инструкция, рекомендованные Навыки и Коннекторы.
- `02_Команды_lead-qualifier-nts.md` — 4 слэш-команды для формы «Создать команду»: Имя, Описание, Инструкции.

## Порядок сборки

1. **Загрузить `SKILL.md` в базу знаний пространства**, в подпапку `3_lead-qualifier-nts/` (вместе с остальными справочными файлами агента — они грузятся все сразу для всего пространства, см. `01_Регламент_сопровождения_и_каденция.md`).
2. **Создать агента.** Открыть `01_Агент_lead-qualifier-nts.md` и построчно перенести: Название → поле «Название», Описание → поле «Описание», Инструкция (текст целиком, включая обязательный блок активации навыка первыми двумя предложениями — не сокращать и не переставлять) → поле «Инструкция».
3. **Прикрепить навыки и коннекторы** из списка в конце `01_Агент_lead-qualifier-nts.md`: ДатаРеестр (MCP) — для проверки контрагента. Веб-поиск — для групп критериев 4 и 6 из criteria_nts.md.
4. **Создать 4 команды.** Слэш-команды в GigaCowork — общий пул на пространство, поэтому имя каждой начинается с номера агента (`3.1`, `3.2` …). Для каждого блока `02_Команды_lead-qualifier-nts.md` перенести Имя команды, Описание и Инструкции в форму «Создать команду».
5. **Проверить деплой не из администраторского аккаунта** — по правилу `platform_architecture.md`/`agent_package.md`: попросить одного из пилотных пользователей (не того, кто собирал агента) открыть его и выполнить стартовую команду `3.1`. Если навык не подхватился или команда не видна — пересобрать шаг 1–4, не откладывать проверку до общей демонстрации пилотной группе.

## Статус на старте пилота — что ещё не готово к production

Критерии остаются рабочей гипотезой v1 — 10–15 архивных заявок для калибровки клиент не передал. Коннектор ДатаРеестр не развёрнут, оценка контрагента — в имитации. Полный чек-лист — раздел 16 `SKILL.md`, сводный статус доступов по всем 7 агентам — `../../06_Карта_доступа_L1-L2-L3.md`.

## Проверка комплекта

Консистентность полей (числа, названия, ссылки команд на файлы базы знаний) проверена скриптом `build_agent_card.py --kb <база знаний агента>` — результат — см. `run_log.md`, раздел «Прогон гипотез / consistency_check».
