# ЧИТАЙ МЕНЯ — как загрузить

Архив собран так, чтобы загрузить один раз и начать проверку. Ничего
переименовывать, разбирать и досоздавать не нужно.

## Что куда

| Папка из архива | Куда |
|---|---|
| `consolidation-harness/` | **в workspace**, целиком, одной папкой |
| `knowledge_base/` | **в workspace**, как база знаний агента |
| `agent_package/` | **не в workspace** — файлы вставляются в конструктор агента |
| `тестовые_данные_2025/` | **не в workspace** — загружать в сессию при проверке |

Из `agent_package/`:
- `skills/00-agent-skill/SKILL.md` → загрузить как **единственный навык**
- `commands/run-agent.md` → загрузить как **единственную команду**

## Важно про структуру

`run.py` вычисляет путь к правилам как `<папка run.py>/rules`. Папку
`consolidation-harness/` нужно разворачивать **целиком, сохраняя дерево**.
Если содержимое растащить по разным местам или «выпрямить» вложенность,
harness не найдёт `mapping.yaml` и `group.yaml`.

## Что уже внутри

- `consolidation-harness/data/` — **пуста намеренно.** Отчётность не
  хранится в общем пространстве: её загружает пользователь в сессию под
  конкретный период, и агент при старте диалога сам предлагает это
  сделать. Предзагруженные данные привели бы к тому, что агент молча
  посчитал бы прошлый период вместо текущего.
- `тестовые_данные_2025/` — 8 файлов за 2025 г. для проверки по
  протоколу. Копируются в папку сессии, путь указывается в `--data`.
- `knowledge_base/` — 5 файлов методологии. Устаревший
  `shablon_avtomatizacii.xlsx` (формульная модель до перехода на harness)
  **намеренно исключён**: расчёт ведёт harness, а лишний файл может сбить
  агента с толку.
- `rules/template_fingerprint.json` **отсутствует намеренно**. Эталон
  формы фиксирует финансовый директор один раз, командой из шага N2
  протокола. До этого первый прогон вернёт `NO_REFERENCE_TEMPLATE`
  (предупреждение, не блокирует) и `template_mode: from_input` — это
  ожидаемое поведение, а не дефект.

## Первые две команды после загрузки

```bash
cd <workspace>/consolidation-harness

# 1. проверка среды и кода — самая информативная проверка
#    (файлы из тестовые_данные_2025/ предварительно скопировать в data/)
python -m pytest tests/ -q
# ожидание: 26 passed

# 2. состав загруженной отчётности — кого консолидируем
python run.py discover --data <папка сессии с файлами>

# 3. эталонный прогон
python run.py run --data <папка сессии с файлами> --out out
```

Первым в выходной папке появится `00_ЧТО_ТРЕБУЕТ_РЕШЕНИЯ.md` — с него
начинает финансовый директор.

### Контрольные цифры прогона

Проверены двумя независимыми реализациями. Расхождение по любой строке —
дефект, а не погрешность. Абсолютные значения эталона — данные клиента,
в шаблон они не переносятся: при переносе эталон строится заново на
отчётности новой группы, тоже двумя независимыми реализациями.

## Замечание о данных

В `тестовые_данные_2025/` лежит реальная отчётность группы «Клиент-Н».
Если проверка проводится на стенде с более широким кругом доступа, чем
рабочий контур, — используйте синтетику из
`synthetic_data_клиент-н.zip`. Контрольные цифры выше в этом случае
работать не будут: они привязаны к реальным данным 2025 г.

## Про эталон формы отчётности

`rules/template_fingerprint.json` отсутствует, и записать его на платформе
**нельзя**: workspace read-only для всех сессий. Поэтому отпечаток
фиксируется вне платформы:

```bash
python run.py adopt-template --from <файл> --approved-by "<ФИО ФД>"
```

и полученный `rules/template_fingerprint.json` добавляется в бандл при
следующей перезаливке. Команда с флагом `--fingerprint-dir` умеет писать
в произвольную папку, если нужно положить отпечаток в сессию.
