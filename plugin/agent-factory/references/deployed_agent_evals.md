# Уровень развёрнутого агента — приёмочный прогон в пространстве

Четвёртый уровень проверки, и до сентября 2026 единственный пустой. Комплект на
диске меряет `check_delivery.py`, пакет — `build_agent_package.py`, сам скилл —
`selftest.py`. Агент, уже стоящий в пространстве GigaCowork, не мерил никто:
его смотрели глазами, и результат оставался в голове проверяющего.

Правило скилла на этот счёт прямое: **проверка, у которой нет своего уровня, не
существует**. Комплект без базы знаний однажды прошёл структурный аудит именно
так — уровень был пуст, и пустоту приняли за зелёный.

| Уровень | Чем меряется | Что ловит |
|---|---|---|
| сам скилл | `selftest.py` | связность, встроенность находок, ложные срабатывания |
| комплект поставки | `check_delivery.py` | собран ли целиком по целевому составу |
| один пакет | `build_agent_package.py`, `build_agent_card.py` | структура, поля формы, обязательные разделы |
| **развёрнутый агент** | **набор кейсов + `check_run.py`** | **внедрена ли версия и не откатилось ли поведение** |

Верхние три отвечают на вопрос «правильно ли собрано». Четвёртый — на другой:
**«ведёт ли себя так, как собрано»**. Это разные вопросы, и первый на второй не
отвечает: файл может лежать в пространстве и не читаться агентом, имя навыка
может разойтись на один знак, команда может быть создана со старым телом.

## Почему прогон ручной, а вердикт машинный

Агент живёт в пространстве, позвать его из скрипта нельзя. Поэтому прогон
разделён надвое:

1. **человек** задаёт вопросы из набора и вставляет ответы в файл прогона —
   целиком, без пересказа;
2. **машина** выносит вердикт по признакам.

Разделение убирает то самое место, где прогон обычно и ломается, — «ну, в целом
ответил правильно». Пересказанный ответ проверить нельзя: пересказ уже содержит
вывод проверяющего.

## Формат набора кейсов

Файл `проверка/evals_<slug>.md` рядом с базой знаний агента. Один кейс:

```markdown
### Б-4.2 · Ответ начинается контуром источников

**Подать:** «4.1 разбери страницу <URL>»

**Ожидается:** первым блоком — контур источников: издания, реестры,
проектные организации, наши материалы, поимённо.

**Признаки:**
- первая-строка-содержит: контур источников
- строк-таблицы>=: 5
- нет: ТЗ на доработку

**Провал означает:** инструкция команды 4.1 заменена не целиком.
```

**Идентификатор задаёт строгость.** `Б-` — блокирующий: провал означает, что
версия не внедрена, и комплект не передаётся. `О-` — наблюдательный: провал
идёт в отчёт и в бэклог, но передачу не останавливает. `С-` — кейс, ждавший
внешнего условия (коннектора, доступа); строгость у него наблюдательная, а имя
нужно, чтобы видеть, что условие наступило и кейс пора прогонять. Четвёртого
уровня нет намеренно: строгость, назначаемая по ощущению, через месяц
оказывается у всех кейсов разной.

**Блок «Признаки» обязателен.** Кейс без него не считается пройденным никогда —
измеритель выводит «проверить нечем». Это осознанно жёстко: кейс, чьи признаки
описаны прозой, выглядит в наборе полноценным и молча не проверяется ничем.

## Язык признаков

Маленький намеренно. Как только в нём появится «оцени» — вердикт перестанет
быть воспроизводимым, и два человека на одном ответе получат разное.

| Признак | Что проверяет |
|---|---|
| `есть: <текст>` | подстрока присутствует |
| `нет: <текст>` | подстроки нет — запрещённое слово, слаг, чужая формулировка |
| `есть-любое: a \| b` | хотя бы одна из формулировок |
| `есть-все: a \| b` | все перечисленные |
| `первая-строка-содержит: a \| b` | в первых трёх непустых строках ответа |
| `строк-таблицы>=: N` | в ответе есть таблица не короче N строк данных |
| `ссылок>=: N` | столько-то адресов `http…` |
| `цитат>=: N` | столько-то закавыченных фрагментов длиннее восьми знаков |
| `чисел>=: N` | столько-то числовых значений |
| `процентов-нет:` | в ответе нет обещаний вида «+30 %» |

Сравнение нечувствительно к регистру, форме кавычек, дефисам, «ё» и разметке:
жирное имя навыка — обычный markdown, и признак, различающий `«Имя»` и
`**"Имя"**`, проверяет клавиатуру, а не поведение. Этот дефект в проекте уже
случался — на сверке комплекта, где шаблон не допускал звёздочек.

## Формат файла прогона

Файл `проверка/прогон_<ГГГГ-ММ-ДД>.md`. Шапка условий, дальше заголовок с
идентификатором кейса и ответ агента целиком:

```markdown
# Прогон агента № 4 — 2026-09-16

**Условия:** версия агента V11 · пространство «Пилот Клиент-П» · аккаунт участника ·
модель по умолчанию · коннектор ДатаРеестр 4.0.2

### Б-4.1

<ответ агента, скопированный целиком>

### Б-4.2

<следующий ответ>
```

Условия записываются не для порядка: один и тот же набор на другой модели, под
администратором или без коннектора даёт другие ответы, и прогон без условий
нельзя сравнить со следующим.

Вердикт:

```bash
python3 scripts/check_run.py \
    --кейсы  <...>/проверка/evals_4_seo-page-optimizer.md \
    --прогон <...>/проверка/прогон_2026-09-16.md
```

Код возврата 1 — провален блокирующий кейс либо на блокирующий кейс нет
ответа. **Блокирующее не усредняется:** зелёные наблюдательные строки его не
перевешивают.

## Что закрывает этот уровень, а что нет

**Закрывает:** внедрена ли версия; активированы ли навыки и названы ли они
русскими именами; не откатилась ли форма ответа; не вернулось ли запрещённое
поведение — проценты эффекта, ТЗ вместо разбора, «закупок нет» вместо «ранее не
передававшихся нет».

**Не закрывает:** качество разбора по существу. Вердикт «пройден» означает, что
в ответе есть обязательные элементы, а не что ответ полезен. Полезность меряется
на реальных задачах и глазами владельца процесса — и это говорится вслух, иначе
зелёный прогон начинают предъявлять как доказательство ценности.

## Когда прогоняется

| Событие | Что прогоняется |
|---|---|
| Развёртывание новой версии агента | весь набор этого агента |
| Пересборка пространства | блокирующие кейсы всех агентов |
| Перед передачей комплекта в пилот | все наборы; отчёт с датой лежит в проекте |
| После правки навыка «на месте» | блокирующие кейсы затронутого агента |

Набор кейсов и отчёт последнего прогона входят в состав поставки для задачи
«пилот» — `delivery_composition.md`, П12 и П13. Для демонстрации они не
обязательны: там агент показывается по сценарию, а не сдаётся в работу.

## Как набор появляется

Кейсы не сочиняются — они **переносятся из уже найденных дефектов**. Каждый
блокирующий кейс обязан иметь происхождение: прогон, на котором поведение
сломалось, замечание клиента, находка сверки. Кейс, придуманный «на всякий
случай», проверяет воображение автора и первым отмирает при правке навыка.

Практический источник — таблица проверок в руководстве по обновлению агентов:
там уже записано, что спросить и что должно прийти в ответ. Перевод такой
строки в кейс — это дописать блок признаков.

**И обратное правило.** Правка навыка, закрывающая найденный дефект, добавляет
кейс в набор в тот же заход. Правка без кейса откатывается при следующей
пересборке молча — ровно так же, как правка скилла без проверки.
