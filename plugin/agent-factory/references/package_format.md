# package_format.md — пакет агента GigaCowork и его загрузка

Пакет порождается из спецификации (`scripts/build_agent_package.py`) и
проверяется структурным аудитом пакета (`scripts/check_package.py`); полный
источник по устройству пакета, Режиму 0, шлюзу на источник, `id` и версии —
`agent_package.md` (перенесён из исходного скилла дословно); уровень комплекта
проверяет `scripts/check_delivery.py` по `delivery_composition.md`. Правила
формата совпадают с исходным скиллом `gigacowork-agent-scenario`
(`agent_package.md`, редакция 25.08.2026), чтобы пакеты фабрики были
неотличимы от пакетов, собранных консультантом.

## Структура — ровно два файла

```text
<agent-slug>/
├── commands/
│   └── run-agent.md
└── skills/
    └── 00-agent-skill/
        └── SKILL.md
```

Один навык, одна команда. Любые другие файлы и каталоги внутри пакета —
провал аудита: `README.md`, `MANIFEST.md`, `templates/`, `evals/`,
`scripts/`, `demo/` и подобные. Синтетика, спецификация, прогон и пакет
доказательств лежат **рядом**, в комплекте, а не внутри пакета.

## Заголовок `SKILL.md` — контракт загрузки (skill_header.py)

| Поле формы «Создать навык» | Ключ | Откуда порождается |
|---|---|---|
| Имя навыка | `name:` | `имя агента` из спецификации |
| Когда применять | `description:` | одна строка: триггер (блок 5), вход и результат (блок 6), «Не брать навык — …» из Out-of-scope (блок 7) |
| Категория | `category:` | `категория` из спецификации, приведённая к списку формы пространства; иначе «Без категории» |
| Инструкции | тело файла | семнадцать разделов; в «2. Пользователь и триггер» — раздел «Когда использовать (триггеры)» с полным текстом условий |
| — (каталог) | `version:` | N из `версия агента: V<N>` |
| — (каталог) | `tags:` | slug агента и `теги` из спецификации |

Служебные ключи, которые импорт пропускает, а проверяет аудит: `id` (не
меняется никогда), `версия агента: V<N>`, `обновлено:`, `спецификация: <id> ·
<версия> · <отпечаток>`. Проверено пробой на стенде 05.10.2026: загрузка файла
заполняет «Имя навыка», «Когда применять» и «Инструкции»; категорию из
значения каталога не подставила; лишние ключи не мешают. Прежние ключи
`имя навыка`, `когда применять`, `категория`, `version: 1.0.0` платформа не
читает — аудит их отклоняет.

Вторая часть условия отбора («не брать …») важнее первой — навык без границ
подхватывается на соседних запросах.

## Семнадцать разделов и откуда они берутся

| § | Раздел | Источник в спецификации |
|---|---|---|
| 1 | Назначение | блок 1 + гипотеза (блок 3) + класс, контур, доступ |
| 2 | Пользователь и триггер | блок 5 |
| 3 | In-scope | блок 7 |
| 4 | Out-of-scope | блок 7 |
| 5 | Входные данные | блок 6 «Входы» |
| 6 | Внутренние модули выполнения | блок 8 «Шаги» (каждый шаг → модуль с входом, выходом, проверками) |
| 7 | Порядок выполнения | блок 8 правила + фиксированный каркас |
| 8 | Форматы выходных артефактов | блок 6 «Выходы» + шаблон результата |
| 9 | Правила доказательности | фиксированный текст |
| 10 | Работа с неопределённостью | блок 9 (EARS) + маркеры `missing_data`, `conflict_requires_review` |
| 11 | HITL_REQUIRED | блок 10 таблицей |
| 12 | Demo-режим и SIM_TOOL_CALL / SIM_TOOL_RESULT | контур, `external_write=false` |
| 13 | Защита данных и prompt injection | блок 11 + фиксированный текст |
| 14 | Quality gates | восемь гейтов, фиксированный текст |
| 15 | Встроенные acceptance cases | блок 12 |
| 16 | Ограничения pilot / production | блок 11, блок 13 (оракул), блок 15, допущения |
| 17 | Формат итогового ответа | фиксированный текст |

Правила, которые аудит проверяет буквально: разделы ищутся как заголовки
(вырезанный раздел не проходит по вхождению слова в другом месте); восемь
гейтов `scope_check … handoff_check`; пять обязательных случаев; маркеры
`missing_data`, `conflict_requires_review`, `HITL_REQUIRED`; конвенция
`SIM_TOOL_CALL` / `SIM_TOOL_RESULT`; `external_write`.

## Команда `run-agent.md`

Заголовок `name: run-agent`, `description:` одной строкой. Тело: заголовок
`# /<slug>`, строка версии, блок «Активируй навык «<имя>»» — по имени, не по
пути в архиве (агент на платформе путь не видит), параметры запуска
(`Название задачи`, `Контур`, `Источник входных данных: спросить`,
`Папка результата`, `Подтверждённые инструменты`, `Дополнительные
ограничения`) и правила выполнения.

## Архив

`<slug>.zip` пишется только при аудите PASS, с фиксированными метками
времени и порядком файлов: одно и то же содержимое даёт один и тот же
SHA-256, и его можно предъявить как «тот самый пакет».

## Загрузка

- **Поколение 2** (конструктор принимает архив): загрузить `<slug>.zip`.
- **Поколение 1.5** (конструктор карточек): создать навык через «Каталог
  навыков → Создать навык», загрузив `SKILL.md`, — имя, «Когда применять» и
  инструкции заполнятся из файла; категорию выбрать в форме, если не
  подставилась.
  Команду — в карточку агента. Ничего не переводить и не сокращать.
- Поколение неизвестно — собирать по Поколению 2 и записать в комплект,
  что поколение не подтверждено; цена ошибки — переупаковка, не переделка.

## Версия

`id` не меняется никогда; `версия агента` растёт на единицу при каждой
пересборке после правки спецификации и видна во фронтматтере, в команде и
в `СБОРКА.md`. У человека агент уже стоит в пространстве — по версии он
понимает, надо ли переносить заново.
