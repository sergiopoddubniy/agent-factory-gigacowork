# Фабрика агентов GigaCowork

Превращает идею агента в рабочего агента — с доказательствами. Агент здесь
продукт: у него есть спецификация, ворота готовности, комплект поставки по
целевому составу, приёмка и проверка результата. Вместо ощущения —
процедура: спецификация `AGENT_SPEC.md` порождает весь комплект скриптами,
готовность считают ворота demo/pilot, а не обсуждение.

## Маршрут

спецификация → ворота готовности → план добора → комплект поставки по
целевому составу → сверка и приёмка → проверка результата

- **Спецификация — источник правды.** 15 блоков; допущение пишется строкой
  «Допущение:», пробел — «Не знаем:», молчание запрещено.
- **Ворота считают, а не спрашивают.** `spec_readiness.py` даёт вердикт по
  порогам demo (показать) и pilot (измерять); ниже demo комплект не
  порождается. Из находок ворот выводится план добора — что и у кого узнать.
- **Комплект поставки порождается из спецификации** по целевому составу
  (ядро Я1–Я21 + надстройка задачи): навык, карточка, команды, клиентский
  docx, база знаний с картой состава, синтетика, точка входа, журнал,
  приёмочные кейсы.
- **Три проверки**: сверка состава, аудит пакета с отпечатком спецификации,
  пакет доказательств. Никакое число зелёных мягких проверок не перевешивает
  один жёсткий провал.

## Три режима

| Режим | Когда |
|---|---|
| Одиночный агент | один процесс, одна роль, одна джоба |
| Портфель | несколько агентов к одному событию, единое пространство, мастер-сценарий |
| Апгрейд в пилот | показанный агент или портфель переводится на реальные данные |

Задача комплекта — демонстрация, воркшоп или пилот — добавляет к общему
ядру состава свою надстройку и определяет, чем меряется успех.

## Состав плагина

- навык-оркестратор «Фабрика агентов GigaCowork» — правила, режимы, маршрут
  сборки;
- 9 команд: Новый агент, Ворота готовности, План добора, Сборка пакета,
  Комплект поставки, Приёмка, Результат, Портфель агентов, Пилот;
- справочники навыка: пайплайны трёх режимов и {{refs}} тематических файлов
  (перечень — в SKILL.md, раздел «Справочные файлы»), плюс база шаблонов
  с синтетическим демо-шаблоном и пустые копилки — реестр реализованных
  агентов и журнал находок, которые наполняет консультант у себя;
- {{scripts}} скриптов на чистом Python (стандартная библиотека) + 1 JS-помощник
  для docx;
- 2 шаблона (спецификация, приёмочный прогон);
- референсов в витринной сборке нет: агент проектируется и собирается с
  нуля по спецификации, все артефакты порождаются скриптами из неё.

## Примеры запросов

- «нужен агент, который готовит ТЗ по запросу разработчика 1С»
- «собрать ассистента для отдела кадров»
- «проверить готовность спецификации агента»
- «собрать комплект поставки для демонстрации»
- «подготовить воркшоп с портфелем агентов»
- «перевести агентов из демо в пилот»
- «провести приёмку агента»

## Требования

Скрипты — Python 3.10+, стандартная библиотека; для ведения реестра
реализованных агентов локально нужен PyYAML. В песочнице платформы
установка пакетов недоступна — реестр и самопроверки выполняются локально
у консультанта; выходные пути в песочнице — внутри `/session`.
