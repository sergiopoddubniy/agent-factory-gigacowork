# /комплект

**Версия:** V3.3 · 2026-09-25

Активируй навык «Фабрика агентов GigaCowork» и выполни Стадии 2–4в
пайплайна одиночного агента: комплект поставки из спецификации.

## Параметры запуска
Название задачи: комплект поставки агента
Задача: демонстрация | воркшоп | пилот (спросить, если не сказано)
Поколение платформы: 2 | 1.5 (спросить; не подтверждено — собирать по 2 и сказать об этом в handoff)
Спецификация: AGENT_SPEC.md в рабочей папке
Корень поставки: ./поставка (архив для загрузки — рядом, в ./поставка_загрузка)
База знаний: папка с файлами, объявленными в блоке 6 «База знаний:»
Синтетика: папка с демо-файлами по случаям блока 12; калибровка — отдельная папка реальных обезличенных документов
Версия агента: V<N>

## Правила выполнения
- до сборки убедиться, что база знаний и синтетика лежат папками: комплект без базы знаний — заготовка, сборщик его не выдаст (`Ф-БЗ`);
- запустить `python3 scripts/build_delivery.py --spec AGENT_SPEC.md --out ./поставка --задача <задача> --поколение <2|1.5> --version V<N> --kb <папка> --synthetic <папка> [--calibration <папка>] [--responses <папка>] [--acceptance ПРИЁМОЧНЫЙ_ПРОГОН.md] --client «<клиент>» --note «<что изменилось>»`;
- показать `СБОРКА.md` дословно: три раздельные строки — `delivery composition check`, `structural audit`, `platform runtime validation` / `deployed state check`; при любом FAIL комплект не передаётся;
- показать первым файлом точку входа `00_Как_использовать_этот_комплект.md`, затем папку агента (навык, карточка, команды, docx);
- проверить клиентский docx глазами (конвертация в pdf, страницы титула, формата вывода, таблиц) — по `references/design_system.md`;
- при повторной сборке существующей поставки — сверка с прежней редакцией `check_delivery.py --против`, изъятия объявляются в `00_ЧТО_УБРАНО_И_ПОЧЕМУ.md`;
- перед выдачей — `freeze_release.py --заморозить`; закончить `/приёмка`.
