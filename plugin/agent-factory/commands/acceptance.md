# /приёмка

**Версия:** V3.3 · 2026-09-25

Активируй навык «Фабрика агентов GigaCowork» и выполни Стадию 6 — приёмочный
прогон и пакет доказательств.

## Параметры запуска
Название задачи: приёмочный прогон
Контур: demo
Спецификация: AGENT_SPEC.md; пакет: ./комплект/<id>
Файл прогона: ПРИЁМОЧНЫЙ_ПРОГОН.md по шаблону templates/ПРИЁМОЧНЫЙ_ПРОГОН.template.md
Кто проводит: пользователь, желательно не автор спецификации

## Правила выполнения
- подготовить файл прогона из блока 12 спецификации: по одному разделу `### <id случая>` с полями Вход / Ожидание / Факт / Вердикт;
- пользователь запускает случаи в пространстве агента и диктует факт; вердикт ставится по ожиданию из спецификации, не по впечатлению;
- `same_input_twice` — две-три новые сессии на один вход; сравнивать таблицу чек-листа построчно (строк поровну, статус ≥ 90 %, расхождения — только `конфликт`/`вопрос`, не решённые агентом); формулировки не сравнивать;
- уровень развёрнутого агента: кейсы с машинными признаками `01_База_знаний_workspace/<N>_<slug>/проверка/evals_<slug>.md` (порождены из блока 12), ответы агента целиком — в `прогон_<дата>.md` там же; вердикт по форме — `python3 scripts/check_run.py --кейсы … --прогон …`; вердикт по существу — приёмщик в файле прогона;
- запустить `python3 scripts/evidence_bundle.py --spec AGENT_SPEC.md --package ./поставка_загрузка/<id> --acceptance ПРИЁМОЧНЫЙ_ПРОГОН.md --out ./поставка/02_Discovery_спецификация` (или пересобрать `/комплект` с `--acceptance` и `--responses`);
- показать EVIDENCE_BUNDLE.md; каждый FAIL — правка спецификации (блоки 8–12) и пересборка `/комплект`, не правка пакета;
- статус гипотезы результата на этом шаге — «не проверена»; закрытие — `/результат`.
