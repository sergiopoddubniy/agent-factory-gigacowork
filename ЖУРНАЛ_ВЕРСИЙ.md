## V3.4 · 2026-09-28

База шаблонов наполнена наработками исходного скилла. Повод: референсы
копились в папке исходного скилла (демо-пакеты, воркшопы, пилоты) и не
были доступны фабрике; решение автора — накапливать их в открытом
репозитории обезличенными, а в витрину для платформы не переносить.

- **17 шаблонов** в `references/agent_templates/` по четырём функциям:
  логистика (8 — навык и команда запуска), сбыт и маркетинг (5 — навык,

  движка и инвариантов, синтетическая база знаний; код движка не входит —
  он собран под формы исходной группы). Вместе с примером 1С — 18.
- **Обезличивание**: клиенты, группы, контрагенты, провайдер данных и
  домены — условными (Клиент-А/П/Т/Г/Н, Заказчик-Э, Завод-1, Компания А–Г,

  абсолютные цифры отчётности клиента — плейсхолдерами и относительными
  величинами, даты пилотов — «на старте пилота», номера документов клиента
  в именах файлов — нейтральными именами. Карта псевдонимов и стоп-лист —
  у автора, вне Git.
- **Фронтматтер навыка**: `id`, `когда применять`, `категория`, `роль`,
  `джоба`, `происхождение: обезличено`, `источник` — поиск

## V3.3 · 2026-09-25

Витринная сборка для платформы и политика обезличивания. Повод: платформа
ставит плагин только на весь продукт (отдельного тенанта нет), а в первой
сборке увидела референсы, которые «нельзя светить». Решение: GitHub
остаётся полным и накапливает референсы (пример, шаблоны, прогоны) —
принципиальная позиция автора; на платформу уходит отдельная сборка без
референсов и без провенанса, собираемая скриптом и проверяемая шлюзом.

- **Обезличивание репозитория.** Найдены и заменены реальные названия
  клиентов и контрагентов, пережившие первый проход (в `evidence_log.md`,
  `few_shot_patterns.md`, `scenario_template.md`, `agent_card_kit.md`,
  `agent_package.md`, `agent_templates/`, `platform_architecture.md`,
  `knowledge/README.md`, фикстуре `check_run.py`): условные Клиент-П/Б/Э/Д/Т/Н/Ф,
  «Пример-Контрагент», «Пример Технологии», `example-*.ru`; абсолютные
  суммы боевых прогонов заменены относительными; вариант аббревиатуры
  клиента, пропущенный ранее, приведён к Клиент-М.
- `docs/06_Политика_обезличивания.md`: три класса содержимого (запрещено
  везде / провенанс — только GitHub / разрешено везде), псевдонимы, правило
  написания нового урока, режимы шлюза, где живут референсы.
- `scripts/hub_gate.py`: шлюз запретов — даты, суммы, домены вне белого
  списка, ФИО, орг-формы с названием, стоп-слова, псевдоним рядом с датой;
  строгий режим для витрины, мягкий — для репозитория (CI); приватный
  стоп-лист вне Git.
- `scripts/build_hub.py`: витринная сборка в раскладке плагина платформы
  (шаблоны — `templates/hub/`: `plugin.yaml`, `agents/agent-factory.md`,
  `agent.html`, `README.md`, получены от платформы 25.09.2026): без
  `examples/` и шаблонов базы (`--с-примерами` возвращает), копилки пусты,
  провенанс вырезан построчно (в коде строки со строковыми литералами не
  трогаются — там фикстуры), команды в формате платформы, архив с UTF-8
  именами средствами Python; внутри сборки — строгий шлюз и
  `selftest_delivery.py`, `selftest.py` — на источнике; отчёт
  `СБОРКА_ВИТРИНЫ.md` с SHA-256.
- CI: job `hub` собирает витрину на каждый push и кладёт архив артефактом;
  мягкий шлюз на репозитории.
- `docs/03`: раскладка плагина зафиксирована, чек-лист обновлён, 18
  вопросов к платформе — в бэклог; `docs/07_Поставка_витрины.md` — что

- `selftest.py` 118 (+13: шлюз в обоих режимах, витрина — раскладка,

## V3.2 · 2026-09-24

Критерий детерминированного слоя расширен — синхронно с исходным скиллом
v9.11 (`25a74f69`). Повод общий: агент реестра закупок (48 карточек из 285)
собрали как «модель читает страницу», потому что критерий звучал «harness
применим, если есть арифметический инвариант», а агент ничего не вычислял;
задачу решил скрипт консультанта за минуты, одинаково в каждом прогоне.
Инвариант был — соответствия источнику. Седьмая находка, крупнее шести
предыдущих.

- `references/agent_package.md`, `references/computational_core.md` —
  редакции v9.11 дословно: **шесть видов инварианта** (арифметический,
  соответствия источнику, полноты множества, тождества ключа,
  идемпотентности, порядка и диапазона); **тест на исполнителя по шагам, а
  не по агенту** (воспроизводим без модели · есть инвариант · видна ли
  ошибка в ответе · требуется ли суждение); правило «шаг, воспроизводимый
  кодом, модели не поручается»; архитектура «детерминированный источник плюс
  агент сверху» — штатная, с признаками «собрано „модель читает страницу“»;
  пустой результат парсера — состояние; отказ записывается с названным
  инвариантом. Плюс фабричный абзац: где решение живёт в спецификации.
- Новый справочник фабрики `references/extraction_core.md` — извлекающий
  слой: `rules/поля.yaml`, движок, пять правил (пустота двух видов и
  BLOCKING при изменившейся вёрстке; регрессия на снимках источника;
  полнота по конструкции; незнакомая метка — вопрос; агент не «дочитывает»
  поля мимо парсера); исполняемость — песочница или MCP-коннектор.
- Спецификация: подмаркер **`Граница код/модель:`** в блоке 8 — таблица
  «шаг → исполнитель → инвариант → чем проверяется», строка на каждый шаг;

  `Ф-06-ЯДРО` (строки нет, без причины, противоречие таблице).
  `build_agent_package.py` переносит таблицу в §6 навыка агента;
  `build_delivery.py` читает `Ядро:` (расчётное → Я10; оба вида — шаг
  инструкции по сборке про размещение ядра, строка в `СБОРКА.md`).
- `SKILL.md`: правило «Разделение труда между кодом и моделью — по шагам, а
  не по агенту» (4 984 токена, в норме); `pipelines/single_agent.md` — абзац

- Проверки: `selftest.py` 105 (+7), `selftest_delivery.py` 409 (иглы v9.11:
  «Шесть видов инварианта», «шаг, воспроизводимый кодом, модели не
