# Ассистент 1С-разработки — результат

**Задача:** черновик ТЗ на доработку документа «Заявка на закупку» (реквизит «Основание закупки») по письму заказчика · **Дата:** 2026-09-21 · **Контур:** demo

## Результат

### Техническое задание на доработку конфигурации 1С — шаблон компании

Номер ТЗ: присваивается при регистрации (не назначен) · Дата: 2026-09-21 · Инициатор: руководитель отдела закупок (по данным письма) · Аналитик: не указан во входных данных · Статус: черновик

#### 1. Цель и обоснование
Отдел закупок сейчас сообщает основание закупки (номер проекта, договор, служебная записка) в переписке, а не в системе — согласующим приходится запрашивать эту информацию отдельно, и она не попадает в заказ поставщику. Нужно добавить в документ «Заявка на закупку» реквизит «Основание закупки», сделать его обязательным условием перед согласованием, показывать согласующему и переносить в «Заказ поставщику». Заказчик — руководитель отдела закупок.

#### 2. Объекты конфигурации
- **Документ.ЗаявкаНаЗакупку** — новый реквизит «ОснованиеЗакупки», тип Строка(200). На уровне метаданных не обязателен (иначе нельзя сохранить черновик без основания); обязательность обеспечивается программной проверкой при переводе в статус «НаСогласовании» (см. п.3.2). В текущей выгрузке такого реквизита нет — реквизиты 001–010 документа его не содержат.
- **Документ.ЗаявкаНаЗакупку, ФормаДокумента** — добавить поле «Основание закупки» (видно инициатору и согласующему).
- **Документ.ЗаявкаНаЗакупку, ФормаСписка** — добавить колонку «Основание закупки».
- **Документ.ЗаказПоставщику** — существующий реквизит 006 «ОснованиеЗакупки», Строка(150), Необязательный; сейчас при автосоздании из заявки остаётся пустым. Требуется автозаполнение при создании заказа по заявке. См. открытый вопрос №1 в реестре ниже.
- **Обработка.СоздатьЗаказПоЗаявке** — доработать: по выгрузке сейчас переносит Организацию и Подразделение (в комментарий), но не заполняет «ОснованиеЗакупки» заказа. Добавить перенос значения из заявки.

#### 3. Функциональные требования
1. Инициатор заполняет «Основание закупки» (текст, до 200 символов) при создании Заявки на закупку. Источник: письмо, п.1.
2. При попытке перевести Заявку в статус «На согласовании» с незаполненным «Основание закупки» перевод статуса запрещён, выводится сообщение «Укажите основание закупки». Источник: письмо, п.2. Допущение: операцию перевода статуса выполняет тот же инициатор, что создал заявку — явно в письме эта роль не названа (см. реестр вопросов, №3).
3. Согласующий видит значение «Основание закупки» в форме заявки и отдельной колонкой в списке заявок. Источник: письмо, п.3.
4. При создании Заказа поставщику по согласованной Заявке значение «Основание закупки» переносится в одноимённое поле Заказа. Источник: письмо, п.4. См. конфликт по длине поля — реестр вопросов, №1.

#### 4. Печатные формы
Не применяется. Причина: заказчик прямо указал не менять печатные формы («Печатные формы менять не нужно», письмо). Действующая печатная форма «Заказ» уже выводит «ОснованиеЗакупки» заказа (макет ПФ_Заказ, выгрузка) — доработка печатных форм не требуется.

#### 5. Права доступа
По письму с полем работают две роли: инициатор (создаёт и заполняет) и согласующий (просматривает). Сопоставить их с конкретными ролями/профилями групп доступа 1С не удалось: выгрузка описания конфигурации не включает права доступа (примечание выгрузки: «табличные части документов, права доступа и модули в выгрузку не включены»). → `missing_data`.

#### 6. Миграция данных
Не определено. Письмо не говорит, нужно ли заполнять «Основание закупки» для заявок, созданных до внедрения доработки (в любом статусе, включая уже согласованные и отклонённые). Без ответа заказчика раздел не может быть закрыт — вопрос в реестре, №2.

#### 7. Критерии приёмки
1. Инициатор создаёт новую Заявку на закупку → поле «Основание закупки» доступно для ввода и сохраняется вместе с заявкой. (→ п.1 письма)
2. Инициатор пытается перевести заявку с пустым «Основание закупки» в статус «На согласовании» → система показывает сообщение «Укажите основание закупки», статус не меняется. (→ п.2)
3. Согласующий открывает форму заявки и список заявок → видит «Основание закупки» в форме и в колонке списка. (→ п.3)
4. По согласованной заявке создаётся Заказ поставщику → поле «Основание закупки» заказа заполнено значением из заявки, в пределах длины поля, согласованной по вопросу №1. (→ п.4)
5. Печатные формы заявки и заказа не изменены. (→ «Печатные формы менять не нужно»)

#### Реестр открытых вопросов к заказчику
1. **Конфликт длины поля** (`conflict_requires_review`). Письмо просит поле «Основание закупки» в Заявке до 200 символов. Выгрузка конфигурации показывает, что одноимённое поле в «Заказе поставщику» — Строка(150). При прямом переносе текст длиннее 150 символов будет обрезан. Нужно решить: увеличить поле «ОснованиеЗакупки» в «Заказе поставщику» до 200 символов, либо ограничить поле в заявке 150 символами. Агент решение не принимает — обе величины показаны выше, в разделе 2.
2. Нужно ли заполнять «Основание закупки» для заявок, существующих на момент внедрения (см. раздел 6)? В письме не указано.
3. Кто выполняет перевод заявки в статус «На согласовании» — сам инициатор или другая роль? Требование п.2 письма сформулировано в предположении, что это инициатор (по аналогии с п.1); явно в письме роль не названа.

## Неопределённости и допущения
- `conflict_requires_review`: длина поля «Основание закупки» — 200 символов по письму (Заявка) против 150 символов в текущей конфигурации (Заказ поставщику, выгрузка). См. реестр вопросов, №1.
- `missing_data`: права доступа и роли не входят в выгрузку конфигурации — раздел 5 ТЗ заполнен только по ролям, названным в письме, без сверки с профилями доступа 1С.
- `missing_data`: нет данных о необходимости миграции для существующих заявок — раздел 6 ТЗ не может быть закрыт без ответа заказчика.
- Допущение: перевод заявки в статус «На согласовании» выполняет инициатор заявки — явно в письме эта роль не названа (см. реестр вопросов, №3).

Решение по каждому открытому вопросу — за аналитиком и, при необходимости, руководителем направления 1С; по конфликту длины поля — также за архитектором 1С.
