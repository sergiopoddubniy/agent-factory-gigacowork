# Ассистент 1С-разработки — результат

**Задача:** черновик ТЗ на отчёт «Заявки без основания» по письму отдела закупок · **Дата:** 2026-09-21 · **Контур:** demo

## Результат

### Техническое задание на доработку конфигурации 1С — черновик

Номер ТЗ: не присвоен (черновик) Дата: 2026-09-21 Инициатор: руководитель отдела закупок (ФИО в письме не указано) Аналитик: не указан, заполняется аналитиком 1С Статус: черновик

#### 1. Цель и обоснование

После внедрения (по словам заказчика) поля «Основание закупки» отделу закупок нужен еженедельный контроль заявок на закупку, у которых это поле не заполнено, — чтобы отслеживать закупки без указанного основания по каждому подразделению и в целом по компании. Источник: письмо_08_отчёт.md, абзац 1.

Обоснование зависит от вопроса 1 реестра ниже: по выгрузке конфигурации поле «Основание закупки» отсутствует именно у документа «Заявка на закупку» (см. раздел 2).

#### 2. Объекты конфигурации

**Документ.ЗаявкаНаЗакупку («Заявка на закупку»)** — источник данных отчёта. Реквизиты, покрывающие запрошенные колонки:

|---|---|---|---|---|
| 001 | Номер | Строка(11) | Обязательный | автонумерация |
| 002 | Дата | Дата | Обязательный | |
| 004 | Подразделение | СправочникСсылка.Подразделения | Обязательный | подразделение инициатора |
| 005 | Инициатор | СправочникСсылка.Сотрудники | Обязательный | заполняется текущим пользователем |
| 006 | СтатусЗаявки | ПеречислениеСсылка.СтатусыЗаявок | Обязательный | Черновик → НаСогласовании → Согласована / Отклонена |
| 008 | СуммаДокумента | Число(15,2) | Необязательный | рассчитывается по табличной части (табличные части не входят в выгрузку — не проверялось) |

Источник: выгрузка_конфигурации.txt, блок «Документ.ЗаявкаНаЗакупку».

**Реквизит-фильтр «Основание закупки» — `conflict_requires_review`:**
- Из письма: поле «Основание закупки» внедрено и предполагается у «Заявки на закупку» — отчёт назван «Заявки без основания» и строится по заявкам (письмо_08_отчёт.md, абзац 1).
- Из выгрузки: у Документ.ЗаявкаНаЗакупку такого реквизита нет (полный список реквизитов 001–010 не содержит «ОснованиеЗакупки»). Реквизит «ОснованиеЗакупки» (Строка(150), Необязательный) есть только у Документ.ЗаказПоставщику (реквизит 006, «свободный текст… при автоматическом создании из Заявки на закупку остаётся пустым») и у Документ.ПоступлениеТоваровУслуг (реквизит 006, копируется из заказа).
- Оба описания показаны, решение не принимаю — см. вопрос 1 реестра. Раздел 2 закрыт условно, до ответа заказчика.

#### 4. Печатные формы

Не применяется. В письме не запрошено изменение и не упомянута ни одна печатная форма; отчёт запрашивается как список данных, а не как печатная форма документа. Источник: письмо_08_отчёт.md (в тексте нет упоминания печати).

#### 5. Права доступа

Требование 3 раздела 3 предполагает ограничение видимости по подразделению для роли «руководитель подразделения» и полный доступ для «руководителя отдела закупок». Конкретные роли/профили назвать не могу: выгрузка явно исключает права доступа («табличные части документов, права доступа и модули в выгрузку не включены», выгрузка_конфигурации.txt, строка 4). `missing_data`: список ролей/профилей пользователей. Раздел остаётся открытым до вопроса 2.

#### 6. Миграция данных

Не применяется в текущей постановке — отчёт только читает данные, новые реквизиты не создаёт. Статус условный: если по ответу на вопрос 1 потребуется добавить реквизит «Основание закупки» в «Заявку на закупку», раздел нужно будет пересмотреть — нужно ли заполнять его для уже существующих заявок.

#### Реестр открытых вопросов к заказчику

1. **[conflict_requires_review]** В каком документе фактически внедрено поле «Основание закупки» — в «Заявке на закупку» (в текущей выгрузке конфигурации такого реквизита у неё нет) или в «Заказе поставщику» (там реквизит «ОснованиеЗакупки» есть, реквизит 006)? От ответа зависят разделы 2, 3, 6, 7.
   Дополнительно: если ответ — «Заказ поставщику», у этого документа по выгрузке нет реквизитов «Подразделение» и «Инициатор» (они есть только у «Заявки на закупку»); при создании заказа не по заявке подразделение/инициатор определить будет нечем — обработка «Создать заказ по заявке» переносит подразделение только в комментарий (свободный текст), а не в структурированный реквизит (выгрузка_конфигурации.txt, блок «Обработка.СоздатьЗаказПоЗаявке»). Также у заказа другой перечень статусов (Новый/Отправлен/Подтверждён/Закрыт вместо Черновик/НаСогласовании/Согласована/Отклонена). Это может потребовать отдельного решения архитектора 1С.
2. **[missing_data]** Какая ролевая модель определяет подразделение текущего пользователя для ограничения видимости отчёта? Права доступа не входят в выгрузку описания конфигурации.
3. **[missing_data]** Нужна ли автоматическая еженедельная рассылка отчёта по понедельникам (регламентное задание + получатели), или достаточно, что отчёт доступен в меню и открывается пользователем вручную?

## Неопределённости и допущения

- `conflict_requires_review`: реквизит-фильтр «Основание закупки» из письма относится к «Заявке на закупку», но в выгрузке такого реквизита у неё нет — есть только у «Заказа поставщику» и «Поступления товаров и услуг» (см. раздел 2 и вопрос 1).
- `missing_data`: роли/профили пользователей для ограничения видимости по подразделению — права доступа исключены из выгрузки (вопрос 2).
- `missing_data`: способ еженедельной поставки отчёта (ручной просмотр или автоматическая рассылка) не назван в письме (вопрос 3).
- Допущение аналитика: раздел 4 «Печатные формы» помечен «не применяется», так как печать в письме не упоминается; при уточнении заказчиком может измениться.
- Допущение аналитика: раздел 6 «Миграция данных» помечен «не применяется» условно — статус зависит от ответа на вопрос 1.
