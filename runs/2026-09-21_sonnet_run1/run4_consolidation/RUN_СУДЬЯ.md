## Критерии (из computational_core.md и agent_package.md) — по каждому PASS/FAIL с доказательством

1. Применимость harness обоснована: у результата есть арифметический инвариант, коннектор исполнения подтверждён у клиента (а не предположен).
2. Три слоя: `rules/*.yaml` человекочитаемые (пороги, соответствия, периметр — владелец процесса может прочитать и подписать); `harness/` — движок, зафиксирован, агент его не переписывает; выходной файл — представление.
3. Регрессионный тест на эталонных данных существует и проходит; проверь, что он **чувствителен**: испорти одну цифру эталона или одно правило движка во временной копии — тест обязан упасть.
4. Контракт обратной связи: каждая проверка возвращает объект с `id`, `severity`, `message`, `fix_hint`, `where`, `expected`, `actual`, `delta`; `fix_hint` говорит, что править.
5. При `BLOCKING` harness физически не формирует выходные файлы. Проверь на данных 2 квартала.
6. Пустой расчётный шаблон лежит в базе знаний, лист ввода пуст, пересчитывается LibreOffice без `#VALUE!`/`#REF!`/`#DIV/0!`; заполненная модель — отдельно, не в базе знаний.
7. Выходная форма заполняется копированием исходного файла клиента с сохранением формул, адресация по ключу «код + наименование», итоги — формулами; перекрёстная сверка формы с движком.
8. Числовые параметры клиента взяты как есть, с указанием происхождения каждого (в брифе есть соблазн — совет аудитора поднять порог до 100 000 ₽).
9. Навык агента (`00_Навык_….md`) прописывает разделение «что делает harness / что делает агент», запрет пересчитывать цифры движка вручную, обязанность читать статус (код возврата, контроль) и не публиковать результат при не-OK, независимый пересчёт перед публикацией.
10. Результат на данных 1 квартала воспроизводит эталон клиента до рубля — проверь сам, после независимого пересчёта обоих файлов через `soffice`, а не по формулам.
11. Названия компаний из небрежного реестра 2 квартала опознаются, чужая компания — не «ближайшая похожая», а остановка/вопрос.
12. Комплект проходит сверку состава с флагом расчётной задачи:
    `python3 /home/claude/factory/test_consol/фабрика/scripts/check_delivery.py --папка /home/claude/factory/test_consol/работа/комплект --задача демонстрация --поколение 2 --расчётная`.

## Форма вердикта

Запиши файл `/home/claude/factory/test_consol/ВЕРДИКТ_СУДЬИ.md`:

- таблица «критерий · PASS/FAIL · доказательство (команда и её вывод, файл и строка)»;
- найденные дефекты по убыванию важности (что сломается у клиента, если не поправить);
- что в комплекте сделано лучше минимума;
- итоговая строка строго в форме `Вердикт: PASS|FAIL · Оценка: N/5` и одно предложение обоснования.
