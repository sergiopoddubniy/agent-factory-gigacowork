# Инструкция по сборке пространства — Консолидация отчётности «Северный порт»

Единый чек-лист для администратора: порядок подтверждён практикой (`workspace_assembly.md`, «Мастер-инструкция сборки»). Каждый артефакт, который человек ставит руками, назван здесь отдельным шагом и лежит в поставке в одном экземпляре.

Поколение платформы: **2**. Конструктор принимает агента архивом; упаковка — шаг 6.

## Шаги

1. **Создать пространство**, видимость — личное на время сборки, командное к моменту показа (демонстрация).
2. **Загрузить базу знаний** целиком: папка `01_База_знаний_workspace/1_severny-port-consolidation/` одним проходом, по карте состава `00_ЧТО_ЗДЕСЬ_И_ЧЕГО_ЗДЕСЬ_НЕТ.md` — что грузится и что намеренно нет.
3. **Подключить коннектор исполнение кода** — песочница Python 3.11 с openpyxl и pandas, запись в sandbox:/output/, без сети (подтверждён администратором 17.09.2026); минимальная версия коннектора версия 1.0.
4. **Разместить расчётное ядро там, откуда его запускает коннектор исполнения кода** (папки `harness/`, `rules/` из базы знаний): как файлы базы знаний попадают в песочницу — подтвердить у администратора платформы, а не предполагать; затем от лица агента запустить точку входа ядра на пустом шаблоне и убедиться, что код возврата и файл протокола появляются в `sandbox:/output/`. Пока этот шаг не пройден, harness существует только в поставке (`computational_core.md`, «Сначала проверь, есть ли чем исполнять harness»).
5. **Создать навык агента** «Каталог навыков → Создать навык»: поля «Имя навыка», «Когда применять», «Категория» — из фронтматтера `04_Пакеты_агентов/1_severny-port-consolidation_V1_21.09.26/00_Навык_severny-port-consolidation.md`, тело файла — в поле «Инструкции». В поле «Имя навыка» вводится дословно `Консолидация отчётности «Северный порт»`: активация работает по совпадению имени.
6. **Создать агента**: поля карточки — из `04_Пакеты_агентов/1_severny-port-consolidation_V1_21.09.26/01_Карточка_агента_severny-port-consolidation.md` (название, описание, «Инструкция» с блоком активации первыми строками, перечень навыков).
7. **Создать команды** из `04_Пакеты_агентов/1_severny-port-consolidation_V1_21.09.26/02_Команды_severny-port-consolidation.md` — 2 команд, каждая со своим именем (с префиксом 1.), описанием и телом; первой — `1.0 Как со мной работать`.
8. **Упаковать архив для загрузки** (шаг человека перед самой загрузкой): структура `severny-port-consolidation/skills/00-agent-skill/SKILL.md` (содержимое `00_Навык_severny-port-consolidation.md`) + `severny-port-consolidation/commands/run-agent.md` (тело команды `1.1`); готовый архив с SHA-256 лежит вне поставки, в `../severny-port-consolidation_загрузка/` — сверить хеш из `СБОРКА.md`.
9. **Проверить задеплоенное состояние от лица не-администраторского аккаунта**: открыть агента, выполнить `1.0 Как со мной работать` и один эталонный запрос из приёмочных случаев навыка (§15); сверить результат по объёму и структуре. Скудный результат — не «модель так работает», а неподцепившийся навык.
10. **Приёмочный прогон**: случаи из `01_База_знаний_workspace/1_severny-port-consolidation/проверка/evals_severny-port-consolidation.md`, ответы агента целиком — в файл `прогон_<ГГГГ-ММ-ДД>.md` там же; вердикт — `python3 scripts/check_run.py --кейсы … --прогон …` (по форме), приёмщик — по существу.

## Три разные строки в handoff

- `delivery composition check` — комплект собран целиком (скрипт, `СБОРКА.md`);
- `structural audit` — структура пакета (скрипт, `СБОРКА.md`);
- `platform runtime validation` / `deployed state check` — агент работает и виден обычному участнику (человек в интерфейсе, шаг выше). Первые две не означают третью.
