# Расчётное ядро консолидации — что это и как им пользоваться

Архитектура в три слоя (`computational_core.md` фабрики агентов):

```
rules/consolidation_rules.yaml   — правила регламента человекочитаемо: периметр,
                                    порог существенности, соответствие статей счетам,
                                    правила ВГО, список контролей. Владелец процесса
                                    может прочитать и подписать. Меняется регламент —
                                    меняется этот файл, а не код.
harness/                         — движок: арифметика и адресация. Пишется один раз,
                                    фиксируется, покрыт регрессионным тестом на
                                    эталонных данных 1 квартала 2026 (принят банком).
                                    Агент НЕ переписывает код харнеса.
Консолидация_форма.xlsx          — выходная форма (в этой же папке базы знаний,
                                    пустая) — представление, не расчёт.
```

## Как агент этим пользуется (коннектор исполнения кода)

```bash
python3 harness/run.py \
    --osv <ОСВ_компания1.xlsx> <ОСВ_компания2.xlsx> <ОСВ_компания3.xlsx> \
    --vgo <ВГО_реестр.xlsx> \
    --form-template Консолидация_форма.xlsx \
    --out sandbox:/output/<квартал>/ \
    --период "<человекочитаемый период>"
```

Три файла ОСВ подаются в любом порядке — харнес сам распознаёт компанию по
содержимому файла (строка «Организация:»), а не по имени файла или порядку
аргументов.

## Код возврата — часть контракта, не деталь реализации

| Код | Что значит | Что делает агент |
|---|---|---|
| `0` | консолидация выполнена, файлы результата записаны в `--out` | публикует результат пользователю |
| `2` | консолидация **остановлена регламентом** — это штатный, ожидаемый исход (расхождение сверх порога §4.4, несогласованность §4.3, инвестиции не сходятся §4.6, компания вне периметра §1); файла формы нет **намеренно** | публикует `СТОП.md` целиком, форму не публикует и не пытается досчитать вручную |
| `1` | ошибка входа: файл не найден, не читается, формат ОСВ/реестра не распознан харнесом | сообщает, каких данных не хватает или что не читается; не является «не сошлось» |

Пустой протокол (код `0`, но без единой находки WARNING) — это отсутствие
корректировок за квартал, а не то же самое, что «харнес не запускался»:
различить их по коду возврата и по наличию файла `протокол.json` в `--out`.

## Числовые параметры — источник каждого назван

Каждый параметр в `rules/consolidation_rules.yaml` сопровождён ссылкой на
пункт регламента (регламент подготовки консолидированной отчётности группы,
редакция 3 — документ у клиента, в эту базу знаний не входит). Ничего
не выведено и не подобрано: порог существенности 50 000 ₽, соответствие
счетов статьям, правило корректировки и элиминации переписаны из регламента
дословно (`computational_core.md`: «числовой параметр методики, полученный
от клиента, применяется без изменений»).

## Проверка независимым пересчётом

Формулы `F` (сумма по группе) и `I` (консолидировано) в форме — формулы
Excel, унаследованные из утверждённого шаблона; харнес их не пишет и не
пересчитывает сам. Перед публикацией результата агент обязан пересчитать
заполненный файл независимым движком:

```bash
soffice --headless --convert-to xlsx --outdir <папка> <результат.xlsx>
```

и прочитать значения (не формулы) из пересчитанного файла для контроля
«актив − пассив = 0» и остальных контролей протокола. Модель, ни разу не
пересчитанная чужим движком, считается непроверенной, чем бы она ни
выглядела (`computational_core.md`, правило 0).

## Регрессионный тест (у консультанта, не в этой поставке)

Харнес проверен на реальных данных клиента: 1 квартал 2026 воспроизводит
эталон, принятый банком, до рубля (16 тестов, `unittest`, см. пакет
доказательств `EVIDENCE_BUNDLE.md`). Сам файл теста и эталон в эту базу
знаний не входят — эталон является ответом, который агент не должен видеть
(`agent_templates.md`: заполненный образец результата не грузится).
