# Техническое задание на доработку конфигурации 1С — шаблон компании

Номер ТЗ: ______ (присваивается при регистрации)   Дата: 2026-09-21   Инициатор: руководитель отдела закупок   Аналитик: ______ (заполняется аналитиком)   Статус: черновик

## 1. Цель и обоснование
Исключить проведение документов «Заказ поставщику» без указанного основания закупки, чтобы в базе не оставалось заказов без обоснования. Заказчик — руководитель отдела закупок. Источник: письмо_03_конфликт.md.

## 2. Объекты конфигурации
Документ.ЗаказПоставщику — реквизит 006 «ОснованиеЗакупки» (синоним «Основание закупки», Строка(150)), сейчас необязательный (выгрузка_конфигурации.txt). Предлагается сделать обязательным для заполнения при проведении документа. Тип и длина реквизита не меняются, новый реквизит не создаётся.

Статус изменения — `conflict_requires_review` (см. п.5, п.9 чек-листа и Вопрос №1): реквизит участвует в автоматическом создании заказа обработкой «Создать заказ по заявке» из Документ.ЗаявкаНаЗакупку, где такого реквизита нет вовсе; обязательность «всегда» без исключений противоречит этой схеме.

## 3. Функциональные требования

**ФТ1.** При попытке провести документ «Заказ поставщику» с незаполненным реквизитом «Основание закупки» система блокирует проведение и выводит сообщение «Укажите основание закупки».
Источник: письмо_03_конфликт.md, абзац 1.

**ФТ2 (под вопросом — конфликт, Вопрос №1).** Реквизит «Основание закупки» обязателен для заполнения во всех документах «Заказ поставщику», независимо от способа создания. По выгрузке при автоматическом создании заказа из согласованной «Заявки на закупку» (обработка «Создать заказ по заявке») реквизит остаётся пустым, так как в заявке такого реквизита нет. Как должно вести себя такое автоматическое создание — не определено; правило не додумывается агентом.
Источник требования: письмо_03_конфликт.md, абзац 1; источник противоречия: выгрузка_конфигурации.txt, блок «Документ.ЗаказПоставщику» (реквизит 006) и блок «Обработка.СоздатьЗаказПоЗаявке».

**ФТ3.** Инициатор операции — менеджер по закупкам, создающий заказ вручную.
Источник: письмо_03_конфликт.md, абзац 1.

**ФТ4.** Ожидаемый результат: в базе нет ни одного проведённого заказа поставщику без заполненного основания закупки; печатная форма «Заказ» всегда отображает заполненное основание (макет ПФ_Заказ уже использует реквизит — изменения макета не требуются).
Источник: письмо_03_конфликт.md, абзац 1; выгрузка_конфигурации.txt, блок «Документ.ЗаказПоставщику» (строка «Печатные формы»).

## 4. Печатные формы
Не применяется: заказчик прямо указал печатные формы не менять («Печатные формы не менять» — письмо_03_конфликт.md, абзац 2). Макет «Заказ» (ПФ_Заказ) уже выводит реквизит «Основание закупки» — обязательность поля обеспечивает его заполненность на печати без изменения макета.

## 5. Права доступа
Не применяется: доработка не создаёт новых объектов и ролей, меняется только правило заполнения существующего реквизита. Данные о правах доступа в выгрузку не включены (выгрузка_конфигурации.txt, примечание в шапке выгрузки), проверить их агент не может.

## 6. Миграция данных
Определяется ответом заказчика (вопрос №2). В письме не указано, что делать с уже существующими документами «Заказ поставщику», где «Основание закупки» не заполнено.

## 7. Критерии приёмки
- Менеджер по закупкам создаёт «Заказ поставщику» вручную, не заполняет «Основание закупки», пытается провести → система выводит сообщение «Укажите основание закупки», документ не проводится.
- Менеджер по закупкам заполняет «Основание закупки», проводит документ → документ проводится успешно.
- Открывается печатная форма «Заказ» по проведённому документу → основание закупки отображается в печатной форме.
- [Под вопросом, зависит от Вопроса №1] Заказ создаётся автоматически из согласованной «Заявки на закупку» через обработку «Создать заказ по заявке» → ожидаемое поведение не определено до ответа заказчика; по текущей схеме реквизит останется пустым, и такой заказ либо будет заблокирован при проведении новым правилом (что расходится с текущей автоматизацией), либо потребует отдельного сценария заполнения.

## Реестр открытых вопросов к заказчику

**Вопрос №1 (конфликт, `conflict_requires_review`, эскалация архитектору 1С).** Реквизит «Основание закупки» в «Заказе поставщику» сейчас необязателен и не заполняется автоматически при создании заказа из согласованной «Заявки на закупку» — в самой заявке такого реквизита нет, и обработка «Создать заказ по заявке» его не переносит (выгрузка_конфигурации.txt). Требование «обязательно всегда, без исключений» (письмо_03_конфликт.md) технически противоречит этой автоматической схеме. Как заполнять основание для заказов, создаваемых из заявки: переносить как «Заявка на закупку № …», требовать ручного дозаполнения перед проведением, исключить такие заказы из проверки, или иначе? Дополнительно: реквизит копируется в документ «Поступление товаров и услуг» (выгрузка_конфигурации.txt) — нужно ли аналогичное изменение обязательности там, или это вне рамок запроса?

**Вопрос №2.** Что делать с уже существующими документами «Заказ поставщику», где «Основание закупки» не заполнено: оставить как есть, обязать дозаполнить задним числом, или иное? В письме не указано.

## Неопределённости и допущения

- `conflict_requires_review`: обязательность реквизита «Основание закупки» — письмо требует «всегда, без исключений», выгрузка показывает реквизит необязательным и незаполняемым при автоматическом создании заказа из заявки (в заявке такого реквизита нет). Оба описания показаны выше (п.5, п.9, Вопрос №1); какой вариант принять, агент не решает.
- `missing_data`: не выявлено — объект «Заказ поставщику» и реквизит «Основание закупки», названные в письме, присутствуют в выгрузке.
- Допущение аналитика: техническое имя реквизита не меняется (используется существующее ОснованиеЗакупки), поскольку это изменение правила заполнения существующего поля, а не создание нового объекта.
