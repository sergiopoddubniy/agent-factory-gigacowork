### Техническое задание на доработку конфигурации 1С

Номер ТЗ: ______ (присваивается по регламенту) · Дата: 2026-09-21 · Инициатор: руководитель отдела закупок (ФИО в письме не указано) · Аналитик: ______ · Статус: черновик

**1. Цель и обоснование**
После внедрения в конфигурацию поля «Основание закупки» руководитель отдела закупок хочет контролировать заявки на закупку, у которых это поле не заполнено. Нужен отчёт «Заявки без основания», показывающий такие заявки за период. Заказчик — руководитель отдела закупок. *Источник: письмо_08_отчёт.md, тема «Отчёт по заявкам без основания».*

Существенная оговорка: реквизит «Основание закупки» в документе «Заявка на закупку», на котором строится вся задача, не подтверждён выгрузкой конфигурации — см. вопрос №2 (`conflict_requires_review`). Формулировки раздела 3 ниже приведены «как есть», их реализуемость на объекте «Заявка на закупку» зависит от ответа заказчика.

**2. Объекты конфигурации**
- `Документ.ЗаявкаНаЗакупку` («Заявка на закупку») — источник данных отчёта. Используемые реквизиты, все присутствуют в выгрузке: 001 `Номер`, 002 `Дата`, 004 `Подразделение`, 005 `Инициатор`, 006 `СтатусЗаявки`, 008 `СуммаДокумента`. Реквизита «Основание закупки» у этого документа в выгрузке нет — см. вопрос №2. *Источник: выгрузка, блок `Документ.ЗаявкаНаЗакупку`.*
- Справочно, вне подтверждённого объёма: реквизит `ОснованиеЗакупки` (`Строка(150)`, Необязательный) есть у `Документ.ЗаказПоставщику` и копируется в `Документ.ПоступлениеТоваровУслуг`; при автосоздании заказа из заявки обработкой «Создать заказ по заявке» не заполняется, а в самой заявке такого реквизита нет вовсе. *Источник: выгрузка, блоки `Документ.ЗаказПоставщику`, `Документ.ПоступлениеТоваровУслуг`, `Обработка.СоздатьЗаказПоЗаявке`.*
- Новый объект: отчёт «Заявки без основания». Предложение аналитика (требует подтверждения, не вопрос заказчику): техническое имя `Отчет.ЗаявкиБезОснования`.

**3. Функциональные требования**
1. Отчёт выводит список документов «Заявка на закупку» за период с колонками: номер, дата, подразделение, инициатор, статус, сумма. Границы периода письмом не заданы — см. вопрос №3. *Источник: письмо, абзац 1.*
2. Отчёт отбирает только заявки, у которых поле «Основание закупки» не заполнено. Реализуемость на объекте «Заявка на закупку» не подтверждена выгрузкой — см. вопрос №2 (`conflict_requires_review`); требование не может быть закрыто до ответа заказчика. *Источник: письмо, абзац 1.*
3. Отчёт запускается из пункта меню раздела «Закупки». *Источник: письмо: «Запускать из меню «Закупки»».*
4. Доступ к отчёту различается по роли: руководитель подразделения видит заявки только своего подразделения; руководитель отдела закупок видит заявки по всем подразделениям. Соответствие бизнес-ролей техническим ролям/профилям доступа конфигурации не установлено — см. вопрос №1. *Источник: письмо: «Отчёт нужен руководителям подразделений (по своему подразделению) и мне (по всем)».*
5. Отчёт нужен «еженедельно по понедельникам». Механизм не назван: ручной запуск пользователем или автоматическая рассылка — см. вопрос №3. *Источник: письмо: «Хотим видеть его еженедельно по понедельникам».*

**4. Печатные формы**
Не применяется: печатные формы в письме не упомянуты; отчёт не создаёт и не меняет печатные формы документов.

**5. Права доступа**
Нужны минимум два уровня видимости отчёта: по своему подразделению (руководители подразделений) и по всем подразделениям (руководитель отдела закупок). *Источник: письмо, абзац 1.* Выгрузка конфигурации права доступа не включает («Примечание выгрузки: ... права доступа ... не включены»), поэтому какие роли/профили групп доступа существуют или потребуются — не определено. Определяется ответом заказчика (вопрос №1).

**6. Миграция данных**
Не применяется: этим запросом не создаётся новый реквизит документов, миграция существующих данных не требуется. Если по итогам вопроса №2 будет решено добавить реквизит «Основание закупки» в «Заявку на закупку», раздел потребует пересмотра, и заполнение для уже существующих заявок станет отдельным открытым вопросом заказчику — независимо от технической необязательности реквизита.

**7. Критерии приёмки**
1. Открыть меню «Закупки» → выбрать отчёт «Заявки без основания» → форма отчёта открывается.
2. Сформировать отчёт на тестовых данных с известными заявками с пустым и заполненным «Основание закупки» → в отчёте только заявки с пустым основанием, колонки номер/дата/подразделение/инициатор/статус/сумма заполнены корректно. *(Зависит от ответа на вопрос №2.)*
3. Открыть отчёт под пользователем — руководителем подразделения → видны только заявки этого подразделения. *(Зависит от ответа на вопрос №1.)*
4. Открыть отчёт под пользователем — руководителем отдела закупок → видны заявки по всем подразделениям. *(Зависит от ответа на вопрос №1.)*

*(Границы периода в критериях приёмки не заданы до ответа на вопрос №3; тестовое воспроизведение не проводилось — агент к 1С не подключён.)*

**Реестр открытых вопросов к заказчику**
1. Какие роли/профили групп доступа должны получить доступ к отчёту «Заявки без основания»? Нужно ли использовать существующий механизм ограничения по подразделению, или потребуется отдельная настройка? (В выгрузке конфигурации права доступа не включены.)
2. **Конфликт (`conflict_requires_review`, эскалация архитектору 1С).** В письме поле «Основание закупки» названо реквизитом документа «Заявка на закупку». По выгрузке конфигурации у `Документ.ЗаявкаНаЗакупку` такого реквизита нет. Реквизит `ОснованиеЗакупки` (`Строка(150)`, Необязательный) есть у `Документ.ЗаказПоставщику` (используется в печатной форме «Заказ») и у `Документ.ПоступлениеТоваровУслуг` (копируется из заказа); в выгрузке прямо указано, что «в заявке такого реквизита нет». Гипотеза (не подтверждена, статус вопроса не меняет): либо поле добавлено в «Заявку на закупку» уже после даты выгрузки (2026-09-18) и не попало в этот срез, либо заказчик имеет в виду поле «Основание закупки» документа «Заказ поставщику» / «Поступление товаров и услуг», а не «Заявки на закупку». Просим уточнить: актуальна ли выгрузка и есть ли сейчас такое поле в «Заявке на закупку»; если нет — нужно ли добавить новый реквизит именно в «Заявку на закупку» или отчёт должен строиться по другому документу.
3. За какой период отчёт должен показывать данные при каждом запуске (весь период, с начала прошлой недели, календарный месяц, произвольный интервал по выбору пользователя)? И что означает «еженедельно по понедельникам» — ручной запуск пользователем каждый понедельник из меню «Закупки», или нужна автоматическая рассылка (кому и каким способом)?
