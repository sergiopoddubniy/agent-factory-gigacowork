# Как участвовать

Проект принимает правки, у которых есть стенд. Правило в справочнике без
проверки, которая ловит его нарушение, и проверка без мутации, которая
показывает, что она ловит, — не принимаются: за полгода прогонов именно
такие «улучшения» тихо переставали работать.

## Что должно быть зелёным перед pull request

Из `plugin/agent-factory/`:

```bash
python3 scripts/selftest.py             # фабрика: 105 проверок, код 0
python3 scripts/selftest_delivery.py    # исходный скилл: 409/409
python3 scripts/mutate_landed.py        # иглы находок вырезаются и ловятся: 118/118
python3 scripts/mutate_build.py         # порча сборщика ловится: 6/6
python3 scripts/mutate_budget.py        # порча оркестратора ловится: 4/4
python3 scripts/token_budget.py         # SKILL.md в норме: ≤ 5000 токенов, ≤ 500 строк (код 1 из-за суммы справочников — ожидаемо)
```

То же самое запускает CI (`.github/workflows/ci.yml`) на Python 3.10 и 3.12
без сторонних библиотек: скрипты — stdlib. Если правка требует `openpyxl`
или LibreOffice, она обязана деградировать честно — говорить, что проверка
не выполнена, а не молча проходить.

## Где что править

| Хочу изменить | Правлю | Дополнительно |
|---|---|---|
| правило поведения агента или сборки | справочник в `references/` | игла в `selftest_delivery.py` / `mutate_landed.py`, чтобы удаление правила ловилось |
| что порождается из спецификации | `scripts/build_delivery.py`, `scripts/build_agent_package.py` | проверка в `scripts/selftest.py`; пересобрать пример (`README.md`, быстрый старт) с `--date 2026-09-21` |
| ворота готовности | `scripts/spec_readiness.py` | находка `Ф-NN-ИМЯ` с текстом «что править»; мутация спецификации в `selftest.py` |
| состав поставки | `references/delivery_composition.md` — единственный источник | `check_delivery.py` читает его; оркестратор состав не дублирует |
| маршрут работы | `SKILL.md` — только правила и маршрут | подробности уходят в `references/pipelines/`; бюджет токенов проверяется |
| спецификация агента | `templates/AGENT_SPEC.template.md`, `references/agent_spec.md` | пример `examples/1c-dev-assistant/AGENT_SPEC.md`, версия `S<N>` |

После любой правки — запись в `ЖУРНАЛ_ВЕРСИЙ.md`: версия, дата, что
изменилось и **зачем** (какой сбой это закрывает). Версия во фронтматтере
`SKILL.md` совпадает с журналом.

## Чего в репозитории не бывает

- Клиентских данных: имён компаний и людей, реальных документов, реестров
  агентов клиентов. Пример синтетический; уроки в справочниках называют
  клиентов условно (Клиент-А, Клиент-П, Клиент-М, ДатаРеестр).
- Проверок, переведённых в чек-листы промпта: всё, что можно посчитать,
  считается скриптом с честным кодом возврата (0 — зелёный, 1 — красный,
  2 — ошибка входа).
- Черновиков и параллельных версий файлов.

## Прогоны

Новый прогон — новая папка в `runs/<дата>_<модель>_<имя>/` с промптами,
ответами целиком, вердиктами судей и отчётом `ОТЧЁТ_ПРОГОНА_*.md`. Судья —
отдельная модель, читающая только артефакты; самооценка сборщиком себя не
считается результатом. Материалы прогона — синтетические.
