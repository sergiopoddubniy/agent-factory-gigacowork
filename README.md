# Фабрика агентов GigaCowork

Плагин для GigaCowork, с которым сотрудник компании — аналитик, методолог,
владелец процесса — делает рабочего агента сам: спецификация → ворота
готовности → план добора информации → пакет → приёмка → проверка
результата. Агент здесь — продукт: у него есть спецификация как источник
правды, измеримая гипотеза результата и контракт завершения.

Выросла из скилла `gigacowork-agent-scenario` (движок: формат пакета
GigaCowork, проверки на Python, эталонные разборы как оракул) и рамки
AI-DISRUPT PDLC / Spec-Driven Development (Agent Specification как
первичный артефакт, Discovery как обязательные артефакты, гипотеза
результата, пакет доказательств). Подробно — `docs/00_Концепция.md`.

## Состав

```text
docs/                      концепция, архитектура, пилот Пулково, валидация для платформы,
                           руководство по внедрению Agent Spec в исходный скилл
plugin/agent-factory/      то, что уходит на платформу
  SKILL.md                 оркестратор (7 шагов, ~4–5 тыс. токенов)
  commands/                /новый-агент /ворота /план-добора /собрать /приёмка /результат
  references/              6 справочников
  templates/               шаблон спецификации, шаблон приёмочного прогона
  scripts/                 spec_readiness · consulting_plan · build_agent_package ·
                           check_delivery · evidence_bundle · selftest (stdlib, Python 3.9+)
  examples/1c-dev-assistant/  синтетический пример: спецификация, прогон, план, комплект
```

## Быстрый старт

```bash
cd plugin/agent-factory
python3 scripts/selftest.py -v                                   # 44 проверки, код 0

S=examples/1c-dev-assistant/AGENT_SPEC.md
python3 scripts/spec_readiness.py --spec $S                      # порог demo → PASS
python3 scripts/spec_readiness.py --spec $S --threshold pilot    # порог pilot → FAIL + находки
python3 scripts/consulting_plan.py --spec $S --threshold pilot   # план добора из находок
python3 scripts/build_agent_package.py --spec $S --out /tmp/kit  # пакет + аудит + архив
python3 scripts/evidence_bundle.py --spec $S --package /tmp/kit/demo-1c-dev-assistant \
    --acceptance examples/1c-dev-assistant/ПРИЁМОЧНЫЙ_ПРОГОН.md    # контракт завершения
```

Коды возврата: 0 — зелёный, 1 — красный, 2 — ошибка входа. Стенд
`selftest.py` проверяет это мутациями: ворота обязаны говорить правду.

## Как работает

1. **Спецификация** `AGENT_SPEC.md` — фронтматтер и 15 блоков
   (возможность, PR/FAQ, гипотеза результата, адаптация/перепроектирование,
   пользователь и триггер, входы и выходы, периметр, правила, EARS-строки
   неопределённости, HITL-карта, доступ, приёмочные случаи, эталонные
   разборы, переиспользование, владелец). Допущение — `Допущение: …`,
   пробел — `Не знаем: …`, молчание запрещено.
2. **Ворота** — два порога: demo (можно показать) и pilot (можно измерять).
3. **План добора** выводится из находок ворот: кого, чем, сколько времени
   людей клиента, чем закончится.
4. **Сборка** порождает пакет GigaCowork (ровно два файла, 17 разделов) с
   отпечатком спецификации; аудит — тот же, что в исходном скилле.
5. **Приёмка** — ручной прогон, машинный вердикт, пакет доказательств.
6. **Результат** — гипотеза проверена или явно не подтверждена; только
   тогда READY по порогу pilot.
