# Фабрика агентов GigaCowork

[![CI](https://github.com/sergiopoddubniy/agent-factory-gigacowork/actions/workflows/ci.yml/badge.svg)](https://github.com/sergiopoddubniy/agent-factory-gigacowork/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-blue)
![stdlib only](https://img.shields.io/badge/deps-stdlib%20only-success)

Открытый плагин для GigaCowork, которым консультант или сотрудник компании
делает рабочего агента — или портфель агентов — **с доказательствами**:
спецификация → ворота готовности → план добора → комплект поставки по
целевому составу → сверка и приёмка → проверка результата. Агент здесь
продукт: спецификация как источник правды, измеримая гипотеза результата,
контракт завершения.

Плагин — это папка с `SKILL.md`, командами, справочниками и скриптами на
чистом Python (без зависимостей). Он читается моделью как навык и запускает
скрипты, которые считают ворота, порождают комплект и сверяют его с
целевым составом. Всё, что здесь лежит, добыто прогонами: каждое правило в
справочниках и каждая проверка в скриптах появились после конкретного сбоя.

> **English.** An open-source plugin for GigaCowork (an enterprise agent
> workspace): it turns an agent idea into a shipped agent *with evidence* —
> a 15-block agent spec as the source of truth, machine-checked readiness
> gates (demo / pilot), a consulting plan derived from gate findings, a
> delivery kit generated from the spec against a canonical composition, an
> acceptance run, and an outcome check. Pure Python (stdlib only), 39
> reference docs, 29 scripts, 98 + 403 self-checks, mutation stands. The
> project is in Russian; the reference docs are the product. Start with
> `docs/00_Концепция.md` and `docs/01_Архитектура.md`.

## Зачем

Агент, собранный «по ощущению», не воспроизводится: второй запуск даёт
другой состав ответа, а на приёмке спорят о том, что вообще обещали.
Фабрика заменяет ощущение процедурой.

**Спецификация `AGENT_SPEC.md`** — фронтматтер и 15 блоков. Допущение
пишется строкой `Допущение:`, пробел — `Не знаем:`, молчание запрещено.
Блок 8 несёт чек-лист полноты с критериями закрытия — единицу результата
агента; блок 12 — приёмочные случаи с машинными признаками.

**Ворота считают, а не спрашивают.** `spec_readiness.py` даёт вердикт по
двум порогам — demo (показать) и pilot (измерять); ниже demo комплект не
порождается. Из находок ворот `consulting_plan.py` выводит план добора:
что и у кого узнать.

**Комплект поставки порождается из спецификации** одной командой по
целевому составу (`references/delivery_composition.md`: ядро Я1–Я21 плюс
надстройка задачи — демонстрация, воркшоп, пилот): навык, карточка,
команды, клиентский docx, база знаний с картой состава, синтетика, точка
входа, инструкция по сборке пространства, журнал, приёмочные кейсы. Архив
для конструктора лежит отдельно от поставки.

**Три проверки**: сверка состава (`check_delivery.py`), аудит пакета с
отпечатком спецификации (`check_package.py`), пакет доказательств
(`evidence_bundle.py`). Никакое число зелёных мягких проверок не
перевешивает один жёсткий провал.

**Расчётные агенты** (консолидация, сверка, начисления) получают расчётное
ядро — правила в yaml, детерминированный движок, регрессионный тест на
эталоне, физический стоп при блокирующем нарушении — а не расчёт «в уме»
(`references/computational_core.md`).

## Быстрый старт

Нужен только Python 3.10+. `openpyxl` и LibreOffice — по желанию: для
проверки пустых расчётных шаблонов и независимого пересчёта моделей.

```bash
git clone https://github.com/sergiopoddubniy/agent-factory-gigacowork.git
cd agent-factory-gigacowork/plugin/agent-factory

python3 scripts/selftest.py             # 98 проверок фабрики, код 0
python3 scripts/selftest_delivery.py    # 403 проверки исходного скилла, код 0

E=examples/1c-dev-assistant
python3 scripts/spec_readiness.py --spec $E/AGENT_SPEC.md                    # demo: PASS
python3 scripts/spec_readiness.py --spec $E/AGENT_SPEC.md --threshold pilot  # pilot: FAIL + находки
python3 scripts/consulting_plan.py --spec $E/AGENT_SPEC.md --threshold pilot # план добора
python3 scripts/build_delivery.py --spec $E/AGENT_SPEC.md --out /tmp/поставка \
    --задача демонстрация --version V1 --client "Пример" \
    --kb $E/материалы/база_знаний --synthetic $E/материалы/синтетика \
    --responses $E/материалы/ответы_прогона --acceptance $E/ПРИЁМОЧНЫЙ_ПРОГОН.md
```

Коды возврата везде одинаковы: 0 — зелёный, 1 — красный, 2 — ошибка входа.
Стенды мутаций (`mutate_landed.py`, `mutate_build.py`, `mutate_budget.py`)
проверяют, что проверки ловят порчу: ворота обязаны говорить правду.

### Как это выглядит в работе

В GigaCowork — или в любом агенте, умеющем читать `SKILL.md` и запускать
скрипты, — плагин срабатывает на «нужен агент, который…», «собрать
ассистента для…», «подготовить воркшоп», «перевести в пилот». Команды:
`/новый-агент`, `/ворота`, `/план-добора`, `/собрать`, `/комплект`,
`/приёмка`, `/результат`, `/портфель`, `/пилот`
(`plugin/agent-factory/commands/`).

Готовый комплект глазами —
`plugin/agent-factory/examples/1c-dev-assistant/комплект/`: собран из
спецификации одной командой, прошёл сверку с целевым составом (ядро 55/55,
надстройка 11/11). Порядок чтения: `00_Как_использовать_этот_комплект.md`
→ папка агента в `04_Пакеты_агентов/` → `СБОРКА.md`.

```text

  SKILL.md                  оркестратор: правила, режимы, задачи, маршрут (~5 тыс. токенов)
  commands/                 9 команд
  references/               39 справочников; pipelines/ — стадии трёх режимов
  templates/                шаблон спецификации, шаблон приёмочного прогона
  scripts/                  29 скриптов, stdlib, Python 3.10+
  examples/1c-dev-assistant/  спецификация, материалы, комплект поставки, прогон
docs/                       концепция, архитектура, валидация для платформы,
                            руководство по внедрению AgentSpec в скилл, сверка с исходным скиллом
runs/                       прогоны на Sonnet: промпты, ответы, вердикты, отчёты (run1 → run4)
ЖУРНАЛ_ВЕРСИЙ.md            что менялось и почему

```

## Режимы и задачи

| Режим | Когда | Пайплайн |
|---|---|---|
| Одиночный агент | один процесс, одна роль | `references/pipelines/single_agent.md` |
| Портфель | несколько агентов, воркшоп, единое пространство | `references/pipelines/portfolio.md` |
| Апгрейд в пилот | показанный портфель переводится на реальные данные | `references/pipelines/pilot_upgrade.md` |

Задача комплекта — **демонстрация**, **воркшоп** или **пилот** — добавляет
к общему ядру состава свою надстройку: сценарий показа и запасной
результат; единое пространство и мастер-сценарий; baseline, регламент
сопровождения, карты встраивания, реестр метрик, протокол приёмки.

## Что доказано прогонами

Прогоны лежат в `runs/` целиком — промпты, ответы, вердикты слепых судей.

| Прогон | Что проверяли | Итог |
|---|---|---|
| run1–run3 | агент 1С-разработки: 10 сценариев, метаморфный `same_input_twice` | воспроизводимость 10/10 статусов чек-листа в трёх сессиях |
| run4 | агент консолидации отчётности: поймёт ли сборщик по плагину, что нужно расчётное ядро | сборщик сам собрал правила yaml, движок и 16 тестов; эталон до рубля, физический стоп при BLOCKING; слепой приёмщик — PASS 4/5, дефекты фабрики закрыты в V3.1 |

## Откуда это

Фабрика выросла из скилла `gigacowork-agent-scenario` (v9.10), выверенного
на живых пилотах: три режима, целевой состав поставки, 30 справочников и
20 скриптов, каждый — ответ на конкретный сбой. В фабрике он лежит целиком
(`docs/05_Сверка_с_исходным_скиллом.md`), а поверх добавлены спецификация
как источник правды и порождение из неё всего, что порождается. Рамка —
Spec-Driven Development и AI-DISRUPT PDLC.

Клиентских данных в репозитории нет: реестр реализованных агентов пуст,
база шаблонов начата одним синтетическим примером, имена клиентов в уроках
справочников заменены на условные (Клиент-А, Клиент-П, Клиент-М,
ДатаРеестр), прогоны сделаны на синтетических материалах.

## Статус и открытые вопросы

V3.1 · 2026-09-22. Работает как плагин для агента, умеющего читать
`SKILL.md` и запускать Python. Официальной спецификации плагинов
GigaCowork у проекта нет — раскладка, формат команд и способ доставки на
инстанс записаны как вопросы к платформе в
`docs/03_Валидация_для_платформы.md`. Репозиторий открыт, чтобы эти
вопросы решались на виду, а наработки не зависели от одного пилота.
