# Фабрика агентов GigaCowork

Плагин для GigaCowork, которым консультант или сотрудник компании делает
рабочего агента — или портфель агентов — с доказательствами: спецификация →
ворота готовности → план добора → комплект поставки по целевому составу →
сверка и приёмка → проверка результата. Агент здесь продукт: спецификация
как источник правды, измеримая гипотеза результата, контракт завершения.

Фабрика V3 = скилл `gigacowork-agent-scenario` v9.10 целиком (три режима,
четыре задачи, целевой состав поставки, 30 справочников и 20 скриптов,
добытых прогонами у клиентов) + спецификация агента как источник правды и
порождение из неё всего, что порождается. Рамка — AI-DISRUPT PDLC /
Spec-Driven Development. Подробно — `docs/00_Концепция.md`,
`docs/05_Сверка_с_исходным_скиллом.md`.

и прошедший сверку с целевым составом исходного скилла

## Быстрый старт

```bash
cd plugin/agent-factory
python3 scripts/selftest.py                                      # 98 проверок фабрики, код 0
python3 scripts/selftest_delivery.py                             # 403 проверки исходного скилла, код 0

E=examples/1c-dev-assistant
python3 scripts/spec_readiness.py --spec $E/AGENT_SPEC.md                    # demo PASS
python3 scripts/spec_readiness.py --spec $E/AGENT_SPEC.md --threshold pilot  # pilot FAIL + находки
python3 scripts/consulting_plan.py --spec $E/AGENT_SPEC.md --threshold pilot # план добора
python3 scripts/build_delivery.py --spec $E/AGENT_SPEC.md --out /tmp/поставка \
    --задача демонстрация --version V1 --client "Пример" \
    --kb $E/материалы/база_знаний --synthetic $E/материалы/синтетика \
    --responses $E/материалы/ответы_прогона --acceptance $E/ПРИЁМОЧНЫЙ_ПРОГОН.md
python3 scripts/check_run.py \
    --кейсы  "/tmp/поставка/01_База_знаний_workspace/1_demo-1c-dev-assistant/проверка/evals_demo-1c-dev-assistant.md" \
    --прогон "/tmp/поставка/01_База_знаний_workspace/1_demo-1c-dev-assistant/проверка/прогон_$(date +%F).md"
```

Коды возврата: 0 — зелёный, 1 — красный, 2 — ошибка входа. Стенды
проверяют это мутациями: ворота обязаны говорить правду.

## Как работает

1. **Режим и задача.** Одиночный агент / портфель / апгрейд в пилот;
   продакшн / пилот / воркшоп / демонстрация. До сборки — переиспользование
   (реестр агентов, база шаблонов), уровень агентизации, карта решения.
2. **Спецификация** `AGENT_SPEC.md` — фронтматтер и 15 блоков; допущение —
   `Допущение: …`, пробел — `Не знаем: …`, молчание запрещено. Блок 8 несёт
   чек-лист полноты с критериями закрытия — единицу результата; блок 6 —
   базу знаний и команды; блок 12 — приёмочные случаи с машинными признаками.
3. **Ворота** — demo (показать) и pilot (измерять); **план добора** — из
   находок ворот.
4. **Комплект поставки** порождается из спецификации по целевому составу
   (`delivery_composition.md`): навык, карточка, команды, docx, база знаний,
   синтетика, точка входа, инструкция по сборке, карта джоб, журнал,
   приёмочные кейсы, надстройка задачи; три проверки — состав, пакет,
   доказательства. Архив для конструктора — вне поставки.
5. **Приёмка** — прогон в пространстве, вердикт по форме (`check_run.py`) и
   по существу (приёмщик), пакет доказательств; **результат** — гипотеза
   измерена или явно не подтверждена; READY по порогу pilot — единственное
   состояние «сделано».
