# Валидация плагина командой платформы GigaCowork

Версия 1 · 2026-09-21 · адресат — команда плагинов (Д. Лейтнер)

## Что передаётся

Папка `plugin/agent-factory/` целиком: `SKILL.md` (оркестратор), `commands/`
(6 команд), `references/` (6 файлов), `templates/` (2), `scripts/` (7,
Python 3.9+, только стандартная библиотека), `examples/1c-dev-assistant/`
(спецификация, прогон, план, порождённый комплект). Клиентских данных в
папке нет: пример синтетический.

## Проверка за пять минут

```bash
cd plugin/agent-factory
python3 scripts/selftest.py -v          # ожидается: проверок 44, провалов 0, код 0
python3 scripts/spec_readiness.py --spec examples/1c-dev-assistant/AGENT_SPEC.md
python3 scripts/build_agent_package.py --spec examples/1c-dev-assistant/AGENT_SPEC.md --out /tmp/kit
python3 scripts/check_delivery.py --package /tmp/kit/demo-1c-dev-assistant --spec examples/1c-dev-assistant/AGENT_SPEC.md
```

Ожидаемый SHA-256 архива при `--date 2026-09-21` записан в
`examples/1c-dev-assistant/комплект/СБОРКА.md`: одинаковое содержимое даёт
одинаковый архив.

## Чек-лист валидации

| # | Проверка | Как | Ожидание |
|---|---|---|---|
| 1 | Скрипты запускаются в среде плагина | `python3 scripts/selftest.py` из папки плагина | код 0 |
| 2 | Коды возврата честные | любой скрипт на заведомо плохом входе | код 1 (красный) / 2 (нет файла), не 0 |
| 3 | Оркестратор в бюджете контекста | размер `SKILL.md` | ~10 тыс. знаков (≈4–5 тыс. токенов); references — ≈10 тыс. токенов суммарно |
| 4 | Порождённый пакет соответствует формату платформы | `check_delivery.py` на комплекте примера | PASS; ровно два файла; фронтматтер — поля формы «Создать навык» |
| 5 | Команды называют навык по имени, задают «Контур» | `commands/*.md` | все шесть активируют «Фабрика агентов GigaCowork» |
| 6 | Нет клиентских данных | поиск по папке имён клиентов, ИНН, ФИО | пусто |
| 7 | Нет обещаний интеграций | порождённый `SKILL.md` §12, §16 | `external_write=false`, имитация помечена |
| 8 | Пример воспроизводим | пересобрать пример с той же датой | тот же SHA-256 |

## Вопросы к платформе (нужны ответы до установки у клиента)

1. **Раскладка плагина.** Плагин с `SKILL.md` в корне и подпапками
   `commands/ references/ templates/ scripts/ examples/` — допустима? Если
   у платформы своя раскладка (например, `skills/<id>/SKILL.md` + манифест),
   пришлите образец или манифест — переупакуем без изменения содержимого.
2. **Интерпретатор.** Версия Python в среде выполнения плагина; скрипты
   написаны под 3.9+ и не требуют библиотек. Есть ли ограничения на
   `subprocess` (selftest запускает скрипты как процессы)?
3. **Файловая система.** Может ли скрипт писать в рабочую область сессии
   (комплект, план, пакет доказательств) и читает ли пользователь эти
   файлы из пространства? Сохраняются ли они между сессиями?
4. **Лимиты.** Время выполнения одного скрипта (selftest — до 10 с), размер
   выходных файлов, число файлов в рабочей области.
5. **Команды.** Формат файла команды (`name / summary / version` во
   фронтматтере и тело) — совпадает с тем, что принимает конструктор?
   Русские имена команд (`/новый-агент`) — допустимы или нужны латинские?
6. **Поколение конструктора** на тестовом инстансе Пулково: архивом
   (Поколение 2) или карточками (1.5)? От этого зависит инструкция
   загрузки в `references/package_format.md`.
7. **Реестр агентов.** Есть ли на платформе каталог уже созданных агентов,
   к которому плагин может обращаться для блока 14 «Переиспользование»?
   Если нет — блок заполняется по `examples/` и вручную.
8. **Обновления.** Как доставляется новая версия плагина на инстанс
   клиента и как пользователь видит версию (у нас — `версия агента: V<N>`
   во фронтматтере и `ЖУРНАЛ_ВЕРСИЙ.md`).

## Что мы гарантируем

Единственный источник — репозиторий фабрики; каждая версия имеет запись
в журнале и проходит `selftest.py`; клиентские данные в плагин не
попадают; формат пакета совпадает с исходным скиллом, из которого
плагин вырос, поэтому агенты, собранные фабрикой и консультантом,
неотличимы для платформы.
