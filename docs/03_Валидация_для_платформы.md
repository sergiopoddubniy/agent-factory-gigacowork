# Валидация плагина командой платформы GigaCowork

Версия 2 · 2026-09-25 · адресат — владелец плагина на платформе (О. Сычугов),
команда плагинов (Д. Лейтнер).

## Что передаётся

**Витринная сборка** — архив `dist/agent-factory_hub_V<N>.zip`, который
собирает `scripts/build_hub.py` из `plugin/agent-factory` (`docs/07_Поставка_витрины.md`).
В ней нет референсов (примера агента, шаблонов базы) — по требованию
платформы; агент на ней проектируется с нуля по спецификации. Рядом с
архивом — `СБОРКА_ВИТРИНЫ.md`: состав, SHA-256, отчёт шлюза обезличивания,
результаты проверок внутри сборки.

## Раскладка плагина (получена от платформы 25.09.2026)

Формат, в котором платформа приняла первую сборку, зафиксирован как
шаблоны в `plugin/agent-factory/templates/hub/` и воспроизводится
`build_hub.py`:

```text
agent-factory/
  plugin.yaml                  name, description, category, version, tags
  agents/agent-factory.md      фронтматтер name, description, skills: [agent-factory], temperature; роль, маршрутизация, принципы, границы
  commands/<имя>.md            фронтматтер name (по-русски), description; тело — инструкция
  skills/agent-factory/        SKILL.md, references/, scripts/, templates/  (examples/ — только с --с-примерами)
  agent.html                   витринная карточка плагина
  README.md                    описание для витрины
```

Что в этом формате ещё не подтверждено — в бэклоге вопросов ниже.

## Проверка за пять минут

```bash
# в репозитории
cd plugin/agent-factory
python3 scripts/selftest.py                      # проверок 118, провалов 0, код 0
python3 scripts/selftest_delivery.py             # ИТОГО 411/411, код 0
python3 scripts/hub_gate.py --папка . --мягко    # 0 нарушений класса A
python3 scripts/build_hub.py --out ../../dist    # витрина: строгий шлюз 0, selftest_delivery внутри, архив + СБОРКА_ВИТРИНЫ.md

# внутри распакованного архива витрины
cd agent-factory/skills/agent-factory
python3 scripts/selftest_delivery.py             # ИТОГО 411/411
python3 scripts/hub_gate.py --папка ../.. --строго
```

Полный комплект поставки для агента собирается `scripts/build_delivery.py`
(см. README репозитория) и проходит сверку `scripts/check_delivery.py` по
целевому составу; в витрине пример этого не приложен намеренно — см.
открытый репозиторий.

## Вопросы к платформе — бэклог

Не отправлены: по решению 25.09.2026 переписка не усложняется, ключевой
запрос платформы — отсутствие референсов — закрыт витринной сборкой.
Ответы понадобятся при первом же пилоте на платформе; тогда список уходит
владельцу плагина.

**Формат плагина.** (1) Раскладка выше — официальный формат, есть ли
спецификация или образец? (2) `plugin.yaml`: обязательные поля, допустимые
`category`, формат `version`, ограничения `tags`. (3) Ограничения архива:
размер, число файлов, допустимые типы (`.py`, `.js`, `.md`, `.xlsx`,
`.docx`). (4) **Кириллица в именах файлов и папок** — поддерживается ли
загрузчиком: в первой сборке 55 файлов из 132 пришли с именами вида
`#U041f#U0420…`; витрина собирается Python-архиватором с UTF-8 именами, но
если кириллица не гарантирована, пути соберём латиницей. (5) `commands/*.md`:
какие поля фронтматтера читаются, допустимы ли русские имена, как команды
показываются пользователю; (6) `agent.html` — назначение, обязательность,
требования к оформлению.

**Исполнение.** (7) Исполняет ли платформа Python-скрипты из
`skills/<id>/scripts/` — вся ценность плагина в машинных проверках; если
да: версия Python, `subprocess`, куда пишутся файлы, рабочая папка,
резолв путей `references/`, `scripts/`. (8) Файлы базы знаний пространства
(`harness/*.py`, `rules/*.yaml`) — попадают ли в песочницу коннектора
исполнения кода и под каким путём; если нет — как размещается код ядра.
(9) Справочники навыка загружаются целиком при каждом вызове или по ссылке
из `SKILL.md` — от этого зависит, держим ли 40 справочников или сжимаем.
(10) Может ли плагин писать файлы во время работы (реестр агентов, журнал
находок) и куда. (11) Поле `temperature` в `agents/*.md`, модель, другие
параметры запуска.

**Тенанты, публикация, обновления.** (12) Установка только на весь продукт
— подтвердить; планируется ли «приватный плагин» для списка тенантов; кто
включает плагин в пространстве. (13) Доставка новой версии: повторная
загрузка, автообновление; сосуществование версий; как пользователь видит
версию. (14) Процесс ревью витрины: кто, сколько, результат.

**Критерии обезличивания.** (15) Перечень мест прошлой сборки, признанных
«нельзя светить», — файлы и строки. (16) Письменные критерии витрины;
наша политика трёх классов — `docs/06_Политика_обезличивания.md`.
(17) Кто подписывает соответствие критериям.

**Стенд.** (18) Доступ к тестовому пространству или сессия с инженером
платформы, чтобы прогнать внутри платформы `selftest_delivery.py`, одну
команду плагина и один эталонный запрос — единственный способ закрыть
«platform runtime validation».

## Что мы гарантируем

Единственный источник — репозиторий фабрики; каждая версия имеет запись в
журнале и проходит `selftest.py`, `selftest_delivery.py` и шлюз
обезличивания; клиентские данные и провенанс уроков в витрину не попадают;
формат пакета совпадает с исходным скиллом, из которого плагин вырос,
поэтому агенты, собранные фабрикой и консультантом, неотличимы для
платформы.
