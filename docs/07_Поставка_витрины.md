# 07 · Поставка витрины: что это, что изменилось, почему можно пользоваться

Версия 1 · 2026-09-25. Сопровождает архив `agent-factory_hub_V<N>.zip`,
который собирается `scripts/build_hub.py` из открытого репозитория
`sergiopoddubniy/agent-factory-gigacowork`. Этот документ уходит вместе с
архивом владельцу плагина на платформе; отчёт конкретной сборки —
`СБОРКА_ВИТРИНЫ.md` рядом с архивом.

## Что это

Плагин «Фабрика агентов GigaCowork» в раскладке платформы: `plugin.yaml`,
`agents/agent-factory.md`, девять команд, навык-оркестратор с 40
справочниками, 31 скриптом на чистом Python (стандартная библиотека) и
двумя шаблонами, витринная карточка `agent.html`, `README.md`. Плагин
ведёт пользователя от идеи агента до рабочего агента с доказательствами:
спецификация → ворота готовности → план добора → комплект поставки по
целевому составу → приёмка → проверка результата.

## Что изменилось относительно первой сборки

1. **Референсов нет.** Пример собранного агента (`examples/`) и шаблоны
   базы шаблонов из витрины сняты, база шаблонов пуста, копилки (реестр
   реализованных агентов, журнал находок) пусты. Агент на платформе
   проектируется с нуля по спецификации `AGENT_SPEC.md` и собирается
   скриптами из неё — референс для этого не нужен. Примеры живут и
   накапливаются в открытом репозитории.
2. **Клиентских данных нет.** Все названия компаний, людей, контрагентов,
   доменов и абсолютные суммы из уроков справочников заменены условными
   (`Клиент-А`, `ООО «Пример-Контрагент»`, `example-*.ru`, относительные
   величины); даты пилотов и адреса инстансов вырезаны. Это делает не
   человек, а сборка: `build_hub.py` вырезает провенанс, `hub_gate.py`
   проверяет результат по регулярным выражениям (даты, суммы, домены вне
   белого списка, ФИО, орг-формы с названием, стоп-слова) — ноль
   вхождений, иначе сборка красная. Политика — `docs/06_Политика_обезличивания.md`.
3. **Справочники — полные, не сжатые.** В первой сборке 39 справочников
   были сжаты агентом до 12 (7 400 → 3 500 строк); вместе с провенансом
   ушла часть правил, а проверки продолжали искать их по именам файлов.
   Здесь справочники те же, что в репозитории, — уроки без провенанса.
   Бюджет контекста держится оркестратором: `SKILL.md` ≤ 5 000 токенов,
   справочники читаются по ссылке по мере надобности.
4. **Имена файлов целы.** Первая сборка пришла с 55 файлами из 132 в виде
   `#U041f#U0420…` — архиватор без флага UTF-8. Витрина собирается
   Python-архиватором с UTF-8 именами; кириллических путей в ней четыре
   (шаблон приёмочного прогона, индекс и карта базы шаблонов, индекс
   копилки).
5. **Формат команд — как принял конструктор:** фронтматтер `name`
   (по-русски) и `description`, тело без шапки версии.

## Почему можно пользоваться сейчас

Внутри архива всё проверяется теми же скриптами, что и в репозитории:

```bash
cd agent-factory/skills/agent-factory
python3 scripts/selftest_delivery.py           # 411/411 — правила справочников на месте
python3 scripts/hub_gate.py --папка ../.. --строго   # 0 нарушений — клиентского и провенанса нет
python3 scripts/token_budget.py                # SKILL.md в норме
```

`selftest.py` (118 проверок фабрики) требует пример и поэтому запускается
на источнике сборки — результат записан в `СБОРКА_ВИТРИНЫ.md` вместе с
SHA-256 архива; сборка воспроизводится из репозитория на том же коммите с
тем же SHA-256, а CI собирает её на каждый push артефактом.

Что не проверено и не может быть проверено снаружи — исполнение скриптов
внутри платформы (`platform runtime validation`): это делается один раз на
тестовом пространстве с инженером платформы; чек-лист —
`docs/03_Валидация_для_платформы.md`.

## Про референсы — на будущее

Референс в этом проекте — обезличенный пример полного пути «спецификация
→ комплект» и шаблон агента с картой переноса. Пример 1С-разработки
синтетический от первой до последней строки: в нём нет ни одного реального
объекта, письма или человека, и бояться его не нужно. Ценность плагина для
любого клиента растёт с числом таких примеров — они питают переиспользование
(блок 14 спецификации) и подбор шаблона по джобе, а каждый прогон на них
находит дефекты фабрики раньше клиента. Поэтому референсы накапливаются в
открытом репозитории под той же политикой обезличивания и тем же шлюзом; в
витрину они не переносятся, пока платформа не решит иначе — тогда это один
флаг сборки (`--с-примерами`).
