# Архитектура плагина

Версия 1 · 2026-09-21

## Состав репозитория

```text
Фабрика агентов GigaCowork/
├── README.md                     — что это, как запустить, как проверить
├── CLAUDE.md                     — правила работы в репозитории для Claude Code
├── ЖУРНАЛ_ВЕРСИЙ.md
├── docs/                         — концепция, архитектура, пилот, валидация, руководство для скилла
└── plugin/agent-factory/         — то, что уходит на платформу
    ├── SKILL.md                  — оркестратор для конечного пользователя (7 шагов)
    ├── commands/                 — new-agent, check-spec, plan, build, acceptance, outcome
    ├── references/               — 6 справочников (~10k токенов суммарно)
    ├── templates/                — AGENT_SPEC.template.md, ПРИЁМОЧНЫЙ_ПРОГОН.template.md
    ├── scripts/                  — 6 скриптов + selftest, только stdlib
    └── examples/1c-dev-assistant — спецификация, прогон, план, порождённый комплект
```

## Поток данных

```text
AGENT_SPEC.md ──► spec_readiness.py ──► вердикт demo / pilot, находки Ф-NN-…
      │                 │
      │                 └──► consulting_plan.py ──► ПЛАН_ДОБОРА.md
      │
      └──► build_agent_package.py ──► <id>/skills/00-agent-skill/SKILL.md
                    │                  <id>/commands/run-agent.md
                    │                  <id>.zip · СБОРКА.md · 00_ПЕРЕИСПОЛЬЗОВАНИЕ.md
                    └──► check_delivery.py (аудит, отпечаток спецификации)

ПРИЁМОЧНЫЙ_ПРОГОН.md + пакет + спецификация ──► evidence_bundle.py ──► EVIDENCE_BUNDLE.md/.json
```

Единственный разбор спецификации — `factory_common.py`; все скрипты
читают её через него, поэтому ворота, план, сборка и доказательства не
могут разойтись в трактовке.

## Скрипты

| Скрипт | Вход | Выход | Код возврата |
|---|---|---|---|
| `spec_readiness.py` | спецификация, порог | отчёт / JSON: статусы блоков, находки, допущения, пробелы | 0 порог пройден · 1 нет · 2 вход |
| `consulting_plan.py` | спецификация, порог | план добора (markdown) | 0 · 2 |
| `build_agent_package.py` | спецификация, папка, версия | пакет, архив, СБОРКА.md, переиспользование | 0 PASS · 1 ворота/аудит FAIL · 2 |
| `check_delivery.py` | папка пакета, [спецификация] | audit_status, находки | 0 · 1 · 2 |
| `evidence_bundle.py` | спецификация, пакет, [прогон], порог | EVIDENCE_BUNDLE.md/.json | 0 READY · 1 NOT READY · 2 |
| `selftest.py` | — | 44 проверки на примере и мутациях | 0 · 1 |

Все скрипты: Python 3.9+, только стандартная библиотека, корень — от
расположения файла, NFC-нормализация текста (macOS хранит «ё» и «й»
разложенными). Коды возврата зависят от результата; `selftest.py`
проверяет это мутациями, а не только «зелёный на хорошем».

## Спецификация как контракт

Фронтматтер (id, имя, версия, дата, класс, контур, доступ) и 15 блоков с
каноническими заголовками. Статус блока вычисляется: заполнено /
допущение (`Допущение:`) / отсутствует; строка `Не знаем:` — явный пробел.
Отпечаток — SHA-256 по NFC-тексту, 8 hex-знаков — ставится в пакет
(`спецификация: <id> · <версия> · <отпечаток>`) и сверяется аудитом.

Пороги (`spec_readiness.py`):

| | demo | pilot |
|---|---|---|
| блоки 1, 5, 6, 7, 12 | заполнены | заполнены |
| остальные | допущение разрешено, молчание нет | ни одного отсутствующего |
| блок 3 | поля, если заполнен | шесть полей; бейзлайн не допущение; метрика не намерение |
| блок 9 | ≥ 1 строка EARS | ≥ 3 |
| блок 10 | таблица, если заполнен | строки с ролью в «Кто» |
| блок 12 | 5 обязательных id | + ≥ 2 предметных |
| блок 13 | явно (может быть «Не знаем») | ≥ 2 эталона |
| блок 15 | — | владелец процесса назван |
| класс детерминированный | блоки 2, 4 не требуются | то же |

## Порождение пакета

Таблица «блок → раздел» — в `references/package_format.md`. Части навыка,
не зависящие от задачи (§9, §12, §14, §17, каркас §7), — фиксированный
текст сборщика: так каждый агент фабрики соблюдает конвенции платформы
одинаково. Части, зависящие от задачи (§1–§6, §8, §10, §11, §13, §15,
§16), — из блоков. Шаги блока 8 со стрелкой `→` становятся модулями §6 с
входом и выходом.

## Что остаётся человеку

Интервью и решения по каждой находке — оркестратор предлагает
формулировку, пользователь подтверждает. Прогон — ручной, вердикт по
ожиданию из спецификации. Измерение гипотезы — по методике блока 3.
Скрипты не заменяют суждение; они не дают его пропустить.
